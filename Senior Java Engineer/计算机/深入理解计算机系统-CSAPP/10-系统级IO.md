# 系统级 IO

本章解释 Unix 风格系统如何把设备、文件、管道、网络连接统一抽象为文件描述符。

## 核心问题

为什么在 Linux 中“万物皆文件”？为什么网络 socket、普通文件、终端都可以用类似方式读写？

## Unix I/O

Unix I/O 的核心接口：

- `open`：打开文件或设备。
- `read`：读取字节。
- `write`：写入字节。
- `close`：关闭描述符。

统一抽象的好处是，程序可以用相似方式操作多种 I/O 资源。

## 文件描述符

文件描述符是进程内的小整数，用来引用打开的文件。

常见标准描述符：

- `0`：标准输入。
- `1`：标准输出。
- `2`：标准错误。

每个进程都有自己的文件描述符表。

## 文件类型

Unix 文件不只普通磁盘文件，还包括：

- 普通文件。
- 目录。
- 字符设备。
- 块设备。
- FIFO。
- Socket。
- 符号链接。

这解释了为什么网络连接也可以通过文件描述符管理。

## read 和 write

`read` 和 `write` 操作的是字节流，不理解业务语义。

注意：

- 一次 `read` 不保证读到你想要的完整业务消息。
- 一次 `write` 不保证写完所有字节。
- 网络 I/O 尤其要处理半包、粘包和重试。

Java 的 `InputStream.read`、`SocketChannel.read` 也有类似语义。

## 文件元数据

文件不仅有内容，还有元数据：

- 文件大小。
- 文件类型。
- 权限。
- 所有者。
- 修改时间。
- inode 信息。

后端常见问题：

- 日志文件被删除但磁盘空间没释放，可能因为进程仍持有文件描述符。
- 权限问题导致应用无法读取配置或写日志。
- inode 用尽会导致无法创建新文件。

## 目录

目录本质上是文件名到 inode 的映射。

路径解析过程就是逐级查找目录项，最终定位到目标文件。

## 共享文件

文件相关内核结构通常包括：

- 进程文件描述符表。
- 打开文件表。
- vnode 或 inode 表。

多个描述符可能引用同一个打开文件对象，也可能引用同一个底层文件但拥有不同偏移量。

这对理解 `dup`、重定向、父子进程共享文件很重要。

## I/O 重定向

Shell 的重定向本质是改变文件描述符指向。

例如：

```bash
command > out.txt
```

可以理解为让标准输出 `1` 指向 `out.txt`。

## 标准 I/O 和系统 I/O

C 标准 I/O 在系统调用之上增加了缓冲。

Java 也有类似层次：

- `FileInputStream` 更接近底层字节流。
- `BufferedInputStream` 增加缓冲。
- `Reader` 处理字符编码。
- NIO 提供 Buffer 和 Channel。

缓冲能提升性能，但也可能导致数据没有及时刷出。

## Java 工程师关联

- 文件描述符泄漏会导致 `Too many open files`。
- Socket 也是文件描述符，所以大量连接会消耗 FD。
- 日志、网络、磁盘 I/O 都要关注缓冲和刷盘。
- NIO 的 Channel 和 Buffer 对系统 I/O 抽象更接近。
- 排查线上 I/O 问题时，`lsof`、`strace`、`iostat`、`ss` 很有用。

## 本章一句话

系统级 I/O 用文件描述符把文件、设备、管道和网络连接统一成可读写的字节流。
