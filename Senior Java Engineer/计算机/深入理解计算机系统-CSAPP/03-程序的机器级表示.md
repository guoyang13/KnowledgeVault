# 程序的机器级表示

本章回答一个关键问题：高级语言里的变量、循环、函数调用、数组和结构体，最终在机器层面长什么样？

## 核心问题

CPU 不理解 Java、C、Python，只理解机器指令。高级语言的控制结构和数据结构，最终都会落到寄存器、内存地址、跳转和栈帧上。

## 汇编语言的意义

汇编不是为了日常手写业务代码，而是为了理解：

- 编译器如何翻译高级语言。
- CPU 如何访问数据和执行控制流。
- 函数调用如何保存现场和返回。
- 内存错误为什么会破坏程序控制流。
- 性能瓶颈为什么可能来自几条底层指令。

对 Java 工程师来说，汇编不是主战场，但理解机器级模型能帮助你读懂 JIT、性能分析和崩溃日志。

## 寄存器

寄存器是 CPU 内部的高速存储单元。

常见用途：

- 保存临时计算结果。
- 保存函数参数。
- 保存返回值。
- 保存栈指针。
- 保存程序运行状态。

寄存器数量有限，所以编译器会尽量把热点变量放进寄存器，放不下才频繁访问内存。

## 指令的基本类型

机器指令大致可以分为：

- 数据传送：寄存器和内存之间移动数据。
- 算术逻辑：加减乘、与或非、移位等。
- 控制转移：跳转、条件跳转、函数调用、返回。
- 地址计算：根据基址、偏移、比例因子计算内存地址。

很多看似复杂的高级语言语句，最后会被拆成这些简单指令组合。

## 条件码和分支

CPU 通过条件码记录上一次运算结果的状态，例如：

- 是否为零。
- 是否为负。
- 是否溢出。
- 是否产生进位。

条件判断、`if`、`while`、`for` 通常会变成：

```text
计算条件
设置条件码
根据条件码跳转
```

现代 CPU 会做分支预测。如果预测失败，会浪费流水线中的工作，影响性能。

## 循环的机器级本质

循环不是一种神秘结构，本质是：

1. 初始化状态。
2. 判断是否继续。
3. 执行循环体。
4. 更新状态。
5. 跳回判断位置。

所以循环性能通常受这些因素影响：

- 每轮执行多少指令。
- 是否有分支预测失败。
- 是否频繁访问内存。
- 是否存在数据依赖。

## 函数调用和栈帧

函数调用需要保存和恢复执行现场。

典型栈帧包含：

- 返回地址。
- 局部变量。
- 保存的寄存器。
- 传递给其他函数的参数。

函数调用不是免费的。频繁的小函数调用可能被编译器内联优化。

Java 中的调用过程更复杂，因为涉及字节码、虚方法、动态分派、JIT 内联，但底层最终仍然要落到机器调用和栈帧。

## 数组和指针

数组访问的本质是地址计算。

例如访问 `a[i]`：

```text
元素地址 = 数组起始地址 + i * 元素大小
```

这解释了为什么连续数组通常缓存友好，而链表对缓存不友好。

Java 数组有边界检查和对象头，和 C 数组不同，但连续存储带来的局部性优势仍然存在。

## 结构体和对象布局

C 的结构体字段会按照一定规则放在内存中，可能存在对齐和填充。

Java 对象也有类似布局问题：

- 对象头。
- 实例字段。
- 对齐填充。
- 引用字段。

对象布局会影响内存占用、缓存命中和 GC 压力。

## 缓冲区溢出

机器级视角可以解释为什么缓冲区溢出危险：

- 栈上数据和返回地址可能相邻。
- 写越界可能覆盖控制信息。
- 攻击者可能借此改变程序控制流。

Java 有数组边界检查，天然避免很多 C 类缓冲区溢出，但 JNI、Unsafe、DirectByteBuffer、native 依赖仍可能引入类似风险。

## Java 工程师关联

- JIT 最终生成机器码，热点方法会被编译优化。
- 虚方法调用可能被内联，也可能因为多态太复杂而无法内联。
- 频繁创建小对象会增加内存访问和 GC 压力。
- 数组、结构化数据、紧凑对象布局通常比大量分散对象更缓存友好。
- 读火焰图、perf、async-profiler 时，理解调用栈和机器执行模型很重要。

## 本章一句话

高级语言的变量、分支、循环和函数调用，最终都要变成寄存器、内存地址、指令和跳转。
