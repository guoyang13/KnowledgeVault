# 并发编程

本章讨论多个控制流同时推进的问题。并发可以提升吞吐和响应能力，也会引入竞态、死锁和同步复杂度。

## 核心问题

当多个执行流同时访问共享资源时，如何保证正确性和性能？

## 并发和并行

- 并发：多个任务在时间上交错推进。
- 并行：多个任务在同一时刻真正同时执行。

单核也可以并发，多核才能真正并行。

## 基于进程的并发

每个连接或任务使用一个独立进程。

优点：

- 地址空间隔离，安全性好。
- 一个进程崩溃不容易直接破坏另一个进程。

缺点：

- 创建和切换成本较高。
- 进程间通信更复杂。

## 基于 I/O 多路复用的并发

一个进程可以同时监视多个文件描述符，哪个就绪就处理哪个。

典型机制：

- `select`
- `poll`
- `epoll`
- `kqueue`

适合大量连接但单个连接 I/O 不持续占满 CPU 的场景。

Java NIO 和 Netty 的事件循环模型与这个思路密切相关。

## 基于线程的并发

线程共享同一个进程的地址空间。

优点：

- 共享数据方便。
- 创建和切换成本通常低于进程。
- 能利用多核并行。

缺点：

- 共享数据容易产生竞态。
- 锁和同步增加复杂度。
- 一个线程写坏共享内存，可能影响整个进程。

## 共享变量

多个线程访问同一变量，只要至少一个线程写，就需要考虑同步。

危险点：

- 读-改-写不是原子操作。
- 编译器和 CPU 可能重排序。
- 缓存一致性和可见性会影响结果。

Java 中还要理解 JMM，也就是 Java 内存模型。

## 临界区和竞态

临界区是访问共享资源的一段代码。

竞态发生在：

- 程序结果依赖线程执行顺序。
- 某些执行顺序会产生错误结果。

例如库存扣减、账户余额修改、计数器累加都可能出现竞态。

## 信号量和互斥

信号量可以控制同时进入某段代码或访问某个资源的线程数量。

互斥锁可以看成初始值为 1 的信号量：

- 进入临界区前获取锁。
- 离开临界区后释放锁。

Java 对应工具：

- `synchronized`
- `ReentrantLock`
- `Semaphore`
- `CountDownLatch`
- `Condition`

## 死锁

死锁通常需要四个条件同时满足：

- 互斥。
- 持有并等待。
- 不可抢占。
- 循环等待。

预防方式：

- 固定加锁顺序。
- 减少锁粒度。
- 避免持锁调用外部系统。
- 使用超时锁。
- 用无锁或消息队列模型降低共享状态。

## 线程安全

线程安全不是“加了锁”这么简单，而是：

> 在多线程访问下，程序仍然满足预期不变量。

常见策略：

- 不共享数据。
- 不可变对象。
- 局部变量。
- 原子类。
- 锁。
- 线程安全容器。
- Actor 或事件循环模型。

## 并发性能

并发不是越多越好。

性能受限于：

- CPU 核数。
- 锁竞争。
- 上下文切换。
- I/O 等待。
- 共享缓存行。
- GC 压力。

线程池大小应该根据任务类型调整：

- CPU 密集型：接近 CPU 核数。
- I/O 密集型：可以更多，但要受下游容量约束。

## Java 工程师关联

- `volatile` 保证可见性和一定的有序性，但不保证复合操作原子性。
- `AtomicInteger` 适合简单原子更新，但高竞争下也可能性能下降。
- `ConcurrentHashMap` 解决容器线程安全，不自动解决业务原子性。
- Netty 通过事件循环减少共享状态和锁竞争。
- 数据库事务、Redis Lua、MQ 顺序消息也是分布式层面的并发控制手段。

## 本章一句话

并发的本质是在多个控制流之间协调共享资源，核心难点是正确性、可见性、原子性、顺序性和性能之间的平衡。
