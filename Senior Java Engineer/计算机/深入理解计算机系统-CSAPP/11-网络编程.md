# 网络编程

本章把网络通信放回系统视角：网络连接可以看成跨机器的 I/O，Socket 是应用程序访问网络的接口。

## 核心问题

两个进程不在同一台机器上，如何通信？

答案是：

- 网络协议提供跨机器寻址和传输。
- 操作系统提供 Socket 接口。
- 应用层协议定义业务语义。

## 客户端-服务器模型

典型交互：

1. 服务器监听端口。
2. 客户端发起连接。
3. 服务器接受连接。
4. 双方通过字节流交换数据。
5. 关闭连接。

后端服务、数据库、Redis、MQ、HTTP API 都可以从这个模型理解。

## IP 和端口

- IP 地址定位主机。
- 端口定位主机上的进程或服务。
- 协议决定传输语义，例如 TCP 或 UDP。

一个连接通常由四元组标识：

```text
源 IP + 源端口 + 目标 IP + 目标端口
```

## TCP

TCP 提供可靠字节流：

- 连接建立。
- 有序传输。
- 丢包重传。
- 流量控制。
- 拥塞控制。

但是 TCP 不保留业务消息边界。应用层要自己定义协议边界，例如：

- 固定长度。
- 分隔符。
- 长度字段。
- HTTP 报文格式。

## DNS

DNS 把域名解析为 IP 地址。

线上问题中，DNS 可能带来：

- 解析延迟。
- 缓存过期。
- 解析结果变化。
- 多可用区或多地域路由差异。

## Socket 接口

服务器常见调用链：

```text
socket -> bind -> listen -> accept -> read/write -> close
```

客户端常见调用链：

```text
socket -> connect -> read/write -> close
```

Java 对应：

- `ServerSocket`
- `Socket`
- `SocketChannel`
- Netty Channel

## 字节序

网络协议通常使用大端字节序，也叫网络字节序。

原因是统一跨平台表示，避免不同 CPU 本地字节序造成通信混乱。

只要涉及二进制协议，就要明确：

- 整数宽度。
- 字节序。
- 字符编码。
- 消息边界。
- 版本兼容。

## Web 服务器

Web 服务器本质上是：

- 接收 TCP 连接。
- 解析 HTTP 请求。
- 生成 HTTP 响应。
- 管理并发连接。

更复杂的服务器还要处理：

- 长连接。
- TLS。
- 反向代理。
- 静态资源。
- 动态路由。
- 限流和超时。

## 并发服务器模型

常见方式：

- 每个连接一个进程。
- 每个连接一个线程。
- I/O 多路复用。
- 事件驱动。
- 线程池加非阻塞 I/O。

Java Web 框架和 Netty 就是在这些模型上构建更高级抽象。

## Java 工程师关联

- HTTP 不是魔法，本质上跑在 TCP 字节流上。
- 接口超时可能来自 DNS、连接建立、服务端排队、网络传输或响应读取。
- Netty 的优势来自事件循环、非阻塞 I/O、Buffer 管理和减少线程切换。
- RPC 协议要解决序列化、连接复用、超时、重试、负载均衡、限流等问题。
- 排查网络问题时要区分应用层、传输层、网络层和 DNS。

## 本章一句话

网络编程就是用 Socket 把跨机器通信抽象成可读写的字节流，并在应用层定义协议语义。
