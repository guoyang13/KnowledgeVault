# 存储器层次结构

本章是理解性能问题的核心章节之一：计算机系统用多层存储设备，在容量、速度和成本之间做折中。

## 核心问题

为什么 CPU 很快，但程序仍然经常慢在内存访问上？

因为不同存储设备速度差异巨大。CPU 执行指令很快，但如果数据不在缓存里，就要等待更慢的内存甚至磁盘。

## 存储技术

常见存储层次：

```text
寄存器
L1 Cache
L2 Cache
L3 Cache
主存 DRAM
SSD
磁盘
网络存储
```

大致规律：

- 越靠近 CPU，速度越快、容量越小、成本越高。
- 越远离 CPU，速度越慢、容量越大、成本越低。

## 局部性

缓存有效的根本原因是局部性。

### 时间局部性

刚访问过的数据，短时间内很可能再次访问。

例如循环中反复读取同一个变量。

### 空间局部性

访问某个地址后，附近地址很可能也会被访问。

例如顺序遍历数组。

## 缓存行

缓存不是按单个字节加载，而是按缓存行加载。

常见缓存行大小是 64 字节。

这意味着：

- 访问数组中一个元素，附近元素也可能被带入缓存。
- 顺序访问通常比随机访问快。
- 多线程写同一缓存行的不同变量，也可能互相影响。

## 缓存命中和未命中

- 命中：需要的数据已经在缓存中。
- 未命中：数据不在缓存，需要从更低层加载。

未命中类型：

- 冷未命中：第一次访问，还没进缓存。
- 容量未命中：工作集太大，缓存放不下。
- 冲突未命中：多个地址映射到同一缓存位置，互相替换。

## 组相联缓存

缓存通常分成多个组，每组有若干行。

地址会被拆成：

- 标记位：判断是不是目标块。
- 组索引：定位到哪个组。
- 块偏移：定位到缓存行内具体字节。

理解这个模型有助于解释某些数组访问模式为什么突然变慢。

## 写策略

缓存写入有不同策略：

- 写直达：同时写缓存和下一层存储。
- 写回：先写缓存，替换时再写回下一层。
- 写分配：写未命中时把块加载进缓存。
- 非写分配：写未命中时直接写下一层。

这些策略影响一致性、性能和复杂度。

## 缓存友好代码

基本原则：

- 让常用数据集中。
- 顺序访问数组。
- 避免频繁随机访问。
- 减少工作集大小。
- 热点路径减少对象分散分配。

例子：

```java
for (int i = 0; i < arr.length; i++) {
    sum += arr[i];
}
```

通常比链表遍历更缓存友好，因为数组内存更连续。

## Java 工程师关联

- `ArrayList` 通常比 `LinkedList` 更适合遍历。
- 大量小对象会导致内存分散，降低缓存局部性，并增加 GC 压力。
- 对象字段布局会影响缓存利用率。
- 伪共享会让多线程性能异常下降。
- Redis、数据库、JVM 堆、Page Cache 都可以从“缓存层次”角度理解。

## 和后端性能的关系

很多后端优化可以归结为缓存层次：

- CPU Cache：对象布局、数组访问、锁竞争。
- JVM 堆：对象生命周期、GC。
- 操作系统 Page Cache：文件读写、数据库缓存。
- 应用缓存：本地缓存、Redis。
- 分布式缓存：跨网络访问，延迟更高。

越靠近 CPU 的缓存越快，但容量越小；越远的缓存容量大，但延迟高。

## 本章一句话

程序性能很大程度取决于数据是否能在合适的时间出现在离 CPU 足够近的位置。
