# 虚拟内存

虚拟内存是计算机系统里最重要的抽象之一。它让每个进程都像拥有连续、私有、巨大的内存空间。

## 核心问题

为什么每个进程都可以从类似的地址开始运行，却不会直接踩到其他进程的内存？

答案是虚拟内存。

## 虚拟地址和物理地址

- 虚拟地址：程序看到的地址。
- 物理地址：真实主存中的地址。

CPU 执行程序时产生虚拟地址，内存管理单元 MMU 通过页表把虚拟地址翻译成物理地址。

```mermaid
flowchart LR
    A["程序虚拟地址"] --> B["MMU 地址翻译"]
    B --> C["物理地址"]
    C --> D["主存"]
```

## 地址空间

每个进程都有自己的虚拟地址空间。

典型区域：

- 代码段。
- 只读数据。
- 全局数据。
- 堆。
- 共享库映射区域。
- 栈。
- 内核虚拟内存区域。

这种布局让程序可以用统一模型管理代码和数据。

## 虚拟内存作为缓存

虚拟内存可以看成磁盘和主存之间的一层缓存机制。

- 虚拟页：虚拟内存的固定大小块。
- 物理页：主存中的固定大小块。
- 页命中：虚拟页已经在物理内存中。
- 缺页：虚拟页不在主存，需要从磁盘或文件映射加载。

缺页异常由硬件和操作系统协作处理。

## 页表

页表记录虚拟页到物理页的映射关系。

页表项通常包含：

- 是否有效。
- 物理页号。
- 访问权限。
- 是否被修改。
- 是否被引用。

页表既支持地址翻译，也支持内存保护。

## TLB

页表查询本身也要访问内存，可能很慢。TLB 是地址翻译结果的高速缓存。

- TLB 命中：快速完成虚拟地址到物理地址翻译。
- TLB 未命中：需要查页表。

大工作集、随机访问、大量进程切换都可能降低 TLB 效率。

## 虚拟内存作为内存保护工具

每个进程有独立页表，操作系统可以控制页面权限：

- 可读。
- 可写。
- 可执行。
- 用户态是否可访问。

非法访问会触发异常，例如段错误。

Java 虽然有内存安全机制，但 JVM native 层仍依赖操作系统内存保护。

## 内存映射 mmap

内存映射把文件或匿名对象映射到虚拟地址空间。

用途：

- 加载可执行文件和共享库。
- 文件映射 I/O。
- 进程共享内存。
- 动态内存分配。

Java 中的 `MappedByteBuffer` 就是内存映射文件的接口。

## 动态内存分配

堆内存分配器负责管理运行时申请和释放的内存。

关键问题：

- 如何找到合适的空闲块。
- 如何拆分和合并空闲块。
- 如何减少碎片。
- 如何在速度和空间利用率之间折中。

碎片类型：

- 内部碎片：分配块内部浪费。
- 外部碎片：空闲空间总量足够，但不连续。

## 垃圾收集

垃圾收集自动发现不再可达的对象并回收空间。

基本思想：

- 从根对象出发。
- 标记所有可达对象。
- 未标记对象视为垃圾。
- 回收或整理空间。

Java GC 在此基础上发展出分代、复制、标记清除、标记整理、并发标记、区域化收集等复杂策略。

## 常见内存错误

在 C 程序中常见：

- 解引用空指针。
- 越界访问。
- 使用未初始化内存。
- 释放后继续使用。
- 重复释放。
- 内存泄漏。

Java 避免了很多裸内存错误，但仍可能发生：

- 内存泄漏，常见于缓存、监听器、ThreadLocal。
- 直接内存泄漏。
- 堆外内存占用过高。
- native 崩溃。
- OOM。

## Java 工程师关联

- JVM 堆只是进程虚拟地址空间的一部分。
- `-Xmx` 限制的是 Java 堆，不等于进程全部内存。
- Direct Memory、Metaspace、线程栈、Code Cache 都在堆外。
- Page Cache 会影响文件 I/O 和数据库性能。
- 容器内存限制下，虚拟内存、物理内存和 cgroup 限制要一起看。
- OOM 排查要区分 Java heap、direct memory、native memory、线程数、容器限制。

## 本章一句话

虚拟内存通过地址翻译、分页、保护和映射，让每个进程获得私有连续地址空间，并把主存当成磁盘内容的缓存。
