# 处理器体系结构

本章从“指令如何被 CPU 执行”的角度，解释顺序执行、流水线、冒险和控制逻辑。

## 核心问题

同一套指令集可以有不同 CPU 实现。程序员看到的是指令语义，硬件工程师实现的是内部数据通路和控制逻辑。

## ISA 和微体系结构

指令集架构 ISA 规定：

- 有哪些指令。
- 指令如何编码。
- 寄存器如何命名。
- 每条指令对程序状态产生什么效果。

微体系结构决定：

- 指令如何被取出和译码。
- 数据如何在硬件部件之间流动。
- 是否使用流水线。
- 如何处理数据相关和分支预测。

简单类比：

- ISA 像 Java 语言规范或 JVM 字节码规范。
- 微体系结构像 HotSpot 对规范的具体实现和优化。

## 指令执行的阶段

一条指令常被拆分为多个阶段：

1. 取指：根据 PC 读取指令。
2. 译码：识别指令类型和操作数。
3. 执行：执行算术逻辑或地址计算。
4. 访存：需要时读写内存。
5. 写回：把结果写回寄存器。
6. 更新 PC：决定下一条指令地址。

这套阶段化模型是理解流水线的基础。

## 顺序实现

顺序处理器一次完整执行一条指令，然后再执行下一条。

优点：

- 模型简单。
- 容易验证正确性。

缺点：

- 硬件资源利用率低。
- 吞吐量差。

现实 CPU 通常不会采用简单顺序实现，而会用流水线、乱序执行、分支预测等方式提高吞吐。

## 流水线

流水线把指令执行拆成多个阶段，让多条指令同时处在不同阶段。

类似工厂流水线：

```text
时刻1：指令A取指
时刻2：指令A译码，指令B取指
时刻3：指令A执行，指令B译码，指令C取指
```

流水线提高的是吞吐量，不一定降低单条指令的延迟。

## 流水线冒险

流水线会遇到冒险，也就是下一步无法安全继续。

常见类型：

- 数据冒险：后一条指令需要前一条指令尚未产生的结果。
- 控制冒险：遇到分支跳转，不知道下一条该取哪条指令。
- 结构冒险：多个阶段争用同一个硬件资源。

处理方式：

- 暂停流水线。
- 数据转发。
- 分支预测。
- 插入气泡。

## 分支预测

条件分支会打断顺序取指。CPU 会猜测分支方向并提前执行。

- 预测正确：流水线继续，性能好。
- 预测错误：丢弃错误路径上的工作，重新取正确指令。

这解释了为什么某些看似相同复杂度的代码，实际性能可能因为分支可预测性不同而差很多。

## 吞吐量和延迟

理解性能时要区分：

- 延迟：完成一个任务需要多长时间。
- 吞吐量：单位时间能完成多少任务。

流水线主要提升吞吐量。后端系统也类似：

- 单个请求耗时是延迟。
- 每秒处理请求数是吞吐量。

## Java 工程师关联

- 分支预测影响热点循环性能。
- 数据依赖会限制指令级并行。
- JIT 优化会尝试减少分支、消除冗余检查、展开循环。
- CPU 层的并行和 Java 线程并行不是一回事。
- 低延迟场景要关注缓存、分支、伪共享、内存屏障等因素。

## 本章一句话

CPU 对外呈现顺序执行的指令语义，内部却通过流水线和预测机制并行推进大量工作。
