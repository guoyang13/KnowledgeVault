# 异常控制流

本章讲的是程序控制流如何被操作系统、硬件和事件打断或切换。它是理解进程、系统调用、信号和上下文切换的基础。

## 核心问题

程序看起来是一条连续执行的指令流，但真实系统中会不断发生打断：

- 时钟中断。
- I/O 完成。
- 缺页异常。
- 系统调用。
- 进程切换。
- 信号到达。

这些都会改变程序原本的控制流。

## 异常控制流 ECF

异常控制流指的是控制权不是简单地从一条指令顺序流向下一条指令，而是因为事件转移到其他代码。

它支撑了很多系统能力：

- 操作系统调度。
- 系统调用。
- 多任务。
- 虚拟内存。
- 信号处理。
- 进程管理。

## 异常类型

常见异常类型：

- 中断：来自外部设备，例如定时器、磁盘、网络。
- 陷阱：有意触发，例如系统调用。
- 故障：可能被修复，例如缺页异常。
- 终止：不可恢复的严重错误。

注意这里的“异常”不是 Java `Exception`，而是硬件/操作系统层面的控制转移机制。

## 系统调用

用户程序不能直接操作硬件或内核数据结构，必须通过系统调用请求内核服务。

典型系统调用：

- 进程控制：`fork`、`execve`、`waitpid`。
- 文件 I/O：`open`、`read`、`write`、`close`。
- 网络：`socket`、`bind`、`listen`、`accept`、`connect`。
- 内存：`mmap`、`brk`。

Java 的很多标准库调用底层都会走系统调用。

## 进程

进程是操作系统提供的执行抽象。

一个进程拥有：

- 独立虚拟地址空间。
- 程序计数器和寄存器状态。
- 打开的文件描述符。
- 用户栈和内核栈。
- 进程 ID 和状态。

进程给程序一种错觉：

> 好像自己独占 CPU 和内存。

实际上这是操作系统通过上下文切换和虚拟内存实现的。

## 上下文切换

上下文包含进程运行所需状态：

- 寄存器。
- 程序计数器。
- 栈指针。
- 内存映射。
- 内核数据结构状态。

上下文切换会保存当前进程状态，再恢复另一个进程状态。

上下文切换不是免费操作。线程过多、锁竞争、阻塞 I/O 都可能造成大量切换，影响吞吐和延迟。

## fork、exec 和 wait

Unix 进程控制的经典组合：

- `fork`：复制当前进程，创建子进程。
- `exec`：在当前进程中加载新程序。
- `wait`：等待子进程结束并回收资源。

这解释了 shell 执行命令的基本方式。

Java 中可以通过 `ProcessBuilder` 创建外部进程，底层也会依赖类似机制。

## 信号

信号是操作系统向进程发送异步事件通知的机制。

常见信号：

- `SIGINT`：终端中断，常见于 `Ctrl+C`。
- `SIGKILL`：强制终止，不能被捕获。
- `SIGTERM`：请求进程终止。
- `SIGCHLD`：子进程状态变化。
- `SIGSEGV`：非法内存访问。

信号处理要非常小心，因为它可能在程序执行任意位置发生。

## 进程组和作业控制

Shell 会把相关进程组织成进程组，用于管理前台和后台作业。

例如管道命令：

```bash
ls | sort
```

会产生多个进程，但它们属于同一个作业，可以一起接收终端信号。

## Java 工程师关联

- `kill -15` 是温和终止，应用应该处理优雅停机。
- `kill -9` 是强制终止，应用没有清理机会。
- 容器环境中的 Java 进程也会收到系统信号。
- 线程上下文切换过多会影响服务吞吐。
- `InterruptedException` 是 Java 层协作中断，不等同于 OS 信号。
- JVM 崩溃日志中的 `SIGSEGV` 往往和 native 代码、JIT、Unsafe、JNI 有关。

## 本章一句话

操作系统通过异常控制流打断、恢复和切换程序执行，从而实现系统调用、进程、信号和多任务。
