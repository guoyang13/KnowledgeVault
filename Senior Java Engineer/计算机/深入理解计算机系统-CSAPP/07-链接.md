# 链接

本章解释程序从多个目标文件和库组合成可执行程序的过程。链接把“分散的代码和数据”拼成操作系统可以加载执行的整体。

## 核心问题

一个程序通常不只来自一个源文件，也会依赖标准库、第三方库和运行时库。链接器负责把这些部分连接起来。

## 编译驱动流程

典型 C 程序构建链路：

```mermaid
flowchart LR
    A["源文件 .c"] --> B["预处理 .i"]
    B --> C["编译 .s"]
    C --> D["汇编 .o"]
    D --> E["链接"]
    E --> F["可执行文件"]
```

Java 的构建链路不同，但思想类似：

- `javac` 把源码编译成 `.class`。
- 构建工具打包成 `jar`。
- JVM 类加载器在运行期解析类、方法和字段引用。
- native 库仍然会涉及操作系统级动态链接。

## 目标文件

目标文件通常包含：

- 机器代码。
- 只读数据。
- 已初始化全局数据。
- 未初始化全局数据。
- 符号表。
- 重定位信息。
- 调试信息。

它还不是最终可执行程序，因为里面可能还有未解析的符号和未确定的地址。

## 符号和符号表

符号可以理解为名字到实体的映射。

常见符号：

- 函数名。
- 全局变量名。
- 静态变量名。
- 外部库函数名。

链接器通过符号表判断：

- 这个名字在哪里定义。
- 哪些地方引用了它。
- 是否存在重复定义或未定义引用。

## 符号解析

符号解析要回答：

> 每个引用到底对应哪个定义？

常见问题：

- 同名全局符号冲突。
- 静态库顺序导致找不到符号。
- 强符号和弱符号选择。
- 头文件声明和实际定义不一致。

Java 中类似的问题包括：

- 类找不到：`ClassNotFoundException`。
- 方法签名不匹配：`NoSuchMethodError`。
- jar 冲突：同一个类来自多个依赖版本。

## 重定位

编译时，很多地址还不能确定。链接器需要把代码和数据放到最终位置，并修正引用地址。

重定位做两件事：

- 合并相同类型的节。
- 修改代码和数据中的地址引用。

这解释了为什么程序从目标文件变成可执行文件时，地址会发生变化。

## 可执行目标文件和加载

可执行文件包含操作系统加载程序所需的信息：

- 入口地址。
- 程序段。
- 代码和数据位置。
- 动态链接信息。

加载器负责把可执行文件映射到进程虚拟地址空间，然后跳转到入口开始执行。

## 静态链接和动态链接

### 静态链接

把依赖库代码复制进可执行文件。

优点：

- 部署相对独立。
- 运行时依赖少。

缺点：

- 文件更大。
- 多个程序重复包含相同库代码。
- 库升级需要重新链接。

### 动态链接

运行时或加载时再链接共享库。

优点：

- 多个程序共享库代码。
- 库可独立升级。
- 文件更小。

缺点：

- 运行时依赖更复杂。
- 版本冲突和路径问题更常见。

## 位置无关代码 PIC

共享库需要能加载到不同进程的不同地址，所以代码不能依赖固定绝对地址。

位置无关代码通过间接寻址等方式，让同一份库代码能被多个进程共享。

## 库打桩和插桩

链接机制可以让我们替换或包装某些函数，用于：

- 监控函数调用。
- 统计性能。
- 调试内存分配。
- 做兼容适配。

Java 中类似思想：

- Java Agent。
- 字节码增强。
- AOP。
- 动态代理。
- instrumentation。

## Java 工程师关联

- Maven/Gradle 依赖冲突，本质上也是“符号和版本解析”问题。
- `jar hell` 和动态库版本冲突很像。
- 类加载器隔离类似命名空间隔离。
- JNI、Netty native transport、压缩库、数据库驱动 native 组件会涉及动态库加载。
- 线上 `NoClassDefFoundError`、`UnsatisfiedLinkError` 可以从链接视角理解。

## 本章一句话

链接把分散的代码、数据和库引用解析为一个可加载运行的程序映像。
