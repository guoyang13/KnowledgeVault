## 1. 当前项目中的测试入口

适合调试传统 MVC POST 重定向链路的测试：

```text
spring-webmvc/src/test/java/org/springframework/web/servlet/mvc/method/annotation/
ServletAnnotationControllerHandlerMethodTests.java
```

测试方法：

```text
redirectAttribute(boolean usePathPatterns)
```

成功请求：

```http
POST /messages
Content-Type: application/x-www-form-urlencoded

name=Jeff
```

Controller：

```java
@Controller
static class RedirectAttributesController {

    @InitBinder
    public void initBinder(WebDataBinder dataBinder) {
        dataBinder.setRequiredFields("name");
    }

    @PostMapping("/messages")
    public String sendMessage(
            TestBean testBean,
            BindingResult result,
            RedirectAttributes attributes) {

        if (result.hasErrors()) {
            return "messages/new";
        }

        attributes.addAttribute("id", "1")
                .addAttribute("name", "value");

        attributes.addFlashAttribute(
                "successMessage", "yay!");

        return "redirect:/messages/{id}";
    }
}
```

## 2. 测试的完整主链路

```text
POST /messages，name=Jeff
  -> HttpServlet.service()
  -> FrameworkServlet.doPost()
  -> FrameworkServlet.processRequest()
  -> DispatcherServlet.doService()
  -> DispatcherServlet.doDispatch()
  -> RequestMappingHandlerMapping
  -> RedirectAttributesController.sendMessage(...)
  -> RequestMappingHandlerAdapter
  -> ServletModelAttributeMethodProcessor
       创建TestBean并绑定name=Jeff
  -> ErrorsMethodArgumentResolver
       获取BindingResult
  -> RedirectAttributesMethodArgumentResolver
       创建RedirectAttributes
  -> InvocableHandlerMethod.doInvoke()
  -> Controller返回redirect:/messages/{id}
  -> ViewNameMethodReturnValueHandler
  -> ModelAndView
  -> DispatcherServlet.render()
  -> RedirectView
       展开id=1
       追加name=value
       保存Flash属性successMessage=yay!
  -> 302 Location: /messages/1?name=value
```

结果解释：

```text
id=1
  -> 展开/messages/{id}

name=value
  -> 追加到查询字符串

successMessage=yay!
  -> 保存为Flash属性
  -> 不出现在URL
  -> 重定向后的GET请求读取
```

## 4. 第一遍：只看主流程

按顺序设置断点：

1. `FrameworkServlet.doPost()`
2. `FrameworkServlet.processRequest()`
3. `DispatcherServlet.doService()`
4. `DispatcherServlet.doDispatch()`
5. `DispatcherServlet.getHandler()`
6. `DispatcherServlet.getHandlerAdapter()`
7. `RequestMappingHandlerAdapter.invokeHandlerMethod()`
8. `InvocableHandlerMethod.doInvoke()`
9. Controller 的 `sendMessage()`
10. `HandlerMethodReturnValueHandlerComposite.handleReturnValue()`
11. `DispatcherServlet.processDispatchResult()`
12. `DispatcherServlet.render()`
13. `RedirectView.renderMergedOutputModel()`

第一遍只回答：

```text
请求从哪里进入？
谁找到Controller？
谁调用Controller？
返回值在哪里变成重定向？
```

## 5. 第二遍：深入 HandlerMapping

调用链：

```text
DispatcherServlet.getHandler()
  -> AbstractHandlerMapping.getHandler()
  -> AbstractHandlerMethodMapping.getHandlerInternal()
  -> AbstractHandlerMethodMapping.lookupHandlerMethod()
  -> RequestMappingInfo.getMatchingCondition()
```

重点观察变量：

| 变量 | 观察内容 |
| --- | --- |
| `lookupPath` | 当前查找路径 |
| `directPathMatches` | 直接路径候选项 |
| `matches` | 完整条件匹配结果 |
| `bestMatch` | 最终映射 |
| `handlerMethod` | Controller Bean 与 Method |
| `mappedHandler` | HandlerExecutionChain |

## 10. 阅读每个方法时问五个问题

1. 当前输入是什么？
2. 当前输出是什么？
3. 它是在选择策略，还是执行策略？
4. 正常分支和异常分支在哪里分开？
5. 数据当前在 request、`ModelAndViewContainer`、`ModelAndView`，还是 response？

示例：

```text
HandlerMapping
  输入：HttpServletRequest
  输出：HandlerExecutionChain
  行为：选择策略

ArgumentResolver
  输入：MethodParameter + NativeWebRequest
  输出：一个Java参数值
  行为：执行参数解析策略

ReturnValueHandler
  输入：Controller返回值
  输出：ModelAndViewContainer变化或HTTP响应
  行为：执行返回值处理策略
```

## 11. 调试纪律

第一次不要进入所有循环和工具方法：

- 先用 Step Over 看主线；
- 到策略选择结果后再 Step Into；
- 记录“输入、输出、选中实现”；
- 同一层只研究一个 Resolver；
- REST 和视图链路分开调试；
- 异步请求放到理解同步请求之后。
