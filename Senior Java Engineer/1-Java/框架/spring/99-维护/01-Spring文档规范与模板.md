# Spring 文档规范与模板

## 1. 命名规则

- 目录使用两位数字表达学习顺序，例如 `30-容器启动与Bean创建`。
- 文件名不重复目录职责，不再使用“层”“大全”“三兄弟”等无法稳定描述边界的词。
- 主文档使用概念或机制名称，例如 `BeanDefinition.md`、`Bean创建主流程.md`。
- 案例使用“场景 + 结论”，例如 `配置类字段注入-refresh调用链案例.md`。
- 速查文件名必须包含“速查”，正文原则上不超过约 250 行。
- Q&A 只作临时入口；成熟后合并进主文档 FAQ，并保留重定向文件。

## 2. 文档元数据

```yaml
---
type: canonical
status: draft
topic: Spring Aware
source_version: 6.2.x
aliases: []
---
```

`type` 只使用：

- `navigation`
- `canonical`
- `quick-reference`
- `source-analysis`
- `case-study`
- `boundary`
- `redirect`
- `maintenance`

`status` 只使用：

- `draft`
- `reviewed`
- `merged`
- `archived`
- `active`（仅维护文档）

## 3. 主文档模板

```markdown
# 主题

## 摘要

用三到五句话回答：它是什么、解决什么问题、位于哪条主流程。

## 术语

统一中英文名称、缩写和相似概念。

## 问题与设计动机

先说明没有该机制时会遇到什么问题。

## 核心模型

给出角色、边界和最小关系图。

## 运行机制

按时间或调用顺序解释，不与源码定位绑定。

## 源码证据

标明模块、类名、方法名和关键条件分支。

## 设计权衡

说明适用场景、代价、替代方案和不适用场景。

## 使用与调试

给出最小示例、观察点和断点。

## 常见误区

只保留确实容易混淆的判断。

## 关联主题

链接前置概念、下游机制、案例和速查。

## 版本与参考

记录 Spring Framework 版本和外部资料。
```

## 4. 内容维护规则

1. 同一概念的正式定义只能出现在 `canonical` 文档。
2. 速查只能摘要，不复制主文档的长解释和完整源码。
3. 案例保留输入、执行过程、观察结果和结论，不重复完整理论。
4. 类比必须紧跟正式定义，且明确标记为辅助理解。
5. 源码优先引用 `模块 / 类#方法`，行号只作为临时调试信息。
6. 无法确认是否重复的内容先标记，不直接丢弃。
7. 合并完成后，旧文件改为 `redirect`，至少保留一个重构周期。
8. 每次迁移后运行双链检查，并更新 [[00-Spring知识体系重构映射]]。

## 5. 完成检查

- [ ] 标题与文件职责一致。
- [ ] 有明确的文档类型和源码版本。
- [ ] 摘要能独立回答“是什么、为什么、在哪里”。
- [ ] 没有与其他主文档重复维护同一完整定义。
- [ ] 源码引用以类和方法为主。
- [ ] 案例与主文档之间存在双向链接。
- [ ] 所有内部双链可解析。
