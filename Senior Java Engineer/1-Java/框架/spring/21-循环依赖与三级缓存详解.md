## 一句话

Spring **只对 Singleton + 字段/Setter 注入** 的循环依赖，用 **三级缓存** 提前暴露「半成品 Bean」；**构造器循环、Prototype 循环** 无法解决。

---

## 一、什么是循环依赖？

```java
@Service
class A {
    @Autowired B b;
}

@Service
class B {
    @Autowired A a;
}
```

```text
创建 A → populateBean 需要 B → 创建 B → populateBean 需要 A → 又回到 A
```

若没有机制，会无限递归或永远等对方创建完。

---

## 二、三级缓存

**定义位置：** `DefaultSingletonBeanRegistry.java` L84–94

| 级别 | 字段 | 内容 | 时机 |
|:----:|------|------|------|
| **一级** | `singletonObjects` | 完全初始化好的单例 | `addSingleton()` 之后 |
| **二级** | `earlySingletonObjects` | 早期暴露的实例（半成品或早期代理） | 有人从三级 factory 取出后 |
| **三级** | `singletonFactories` | `ObjectFactory`，用于 **生成** 早期引用 | `addSingletonFactory()` 之后 |

### `getSingleton(beanName)` 查找顺序

**位置：** `DefaultSingletonBeanRegistry.java` L210–231

```text
getSingleton(beanName, allowEarlyReference=true)
  ① singletonObjects.get(beanName)              成品，直接返回
  ② earlySingletonObjects.get(beanName)           早期引用
  ③ singletonFactories.get(beanName)
       factory.getObject()
         → getEarlyBeanReference()               AOP 可能在此提前代理
       移入 earlySingletonObjects，删除 factory
```

## 三、何时注册三级缓存？

**位置：** `AbstractAutowireCapableBeanFactory.doCreateBean()` L601–611

```java
boolean earlySingletonExposure = (mbd.isSingleton()
    && this.allowCircularReferences              // 默认 true；Spring Boot 2.6+ 可配置 false
    && isSingletonCurrentlyInCreation(beanName));

if (earlySingletonExposure) {
    addSingletonFactory(beanName, () -> getEarlyBeanReference(beanName, mbd, bean));
}
```

### 条件

| 条件 | 说明 |
|------|------|
| **Singleton** | Prototype 不缓存 |
| **allowCircularReferences = true** | `AbstractAutowireCapableBeanFactory` L132 默认 true |
| **singletonsCurrentlyInCreation 含 beanName** | 当前 Bean 正在创建 |

### 时机（在 doCreateBean 中的位置）

```text
doCreateBean()
├─ createBeanInstance()              实例化（rawBean，依赖字段还是 null）
├─ addSingletonFactory()             ★ 三级缓存（L611）
├─ populateBean()                    字段 @Autowired — 可能触发嵌套 getBean
├─ initializeBean()                  init + AOP
└─ 早期引用 vs 最终对象一致性校验（L631–657）
```

**关键：** 必须在 **`populateBean` 之前** 暴露，否则 B 要 A 时 A 还不在缓存里。

## 四、经典时间线：A ↔ B 字段注入

```text
1. getBean("a")
     doCreateBean("a")
       createBeanInstance()           → new A()
       addSingletonFactory("a")       → 三级
       populateBean(a)                → 需要 B
         getBean("b")

2. getBean("b")
     doCreateBean("b")
       createBeanInstance()           → new B()
       addSingletonFactory("b")
       populateBean(b)                → 需要 A
         getBean("a")
           doGetBean("a")
             getSingleton("a")        ★ 三级 factory → getEarlyBeanReference → 半成品 A
           注入 B.a = 早期 A
       initializeBean(b)              → B 完成
       addSingleton("b")              → 一级

3. 回到 A
       populateBean(a)                → 注入完整 B
       initializeBean(a)              → A 完成（可能含 AOP 代理）
       addSingleton("a")              → 一级
```

### 调用栈（简化）

```text
getBean(a)
  doCreateBean(a)
    addSingletonFactory(a)
    populateBean(a)
      getBean(b)
        doCreateBean(b)
          populateBean(b)
            getBean(a)
              getSingleton(a)    ← 从缓存拿早期 A，不再完整 doCreateBean
          ...
    initializeBean(a)
```

## 五、与注入方式的关系

| 注入方式 | 循环依赖 | 原因 |
|----------|:--------:|------|
| **字段 / Setter `@Autowired`** | ✅ 三级缓存 | 先 `new` 空壳，populate 时才要依赖 |
| **构造器注入** | ❌ 失败 | 实例化时就要 B，B 也要 A，无法先暴露 |
| **Prototype** | ❌ 失败 | 不进入单例缓存 |
| **`@DependsOn` 成环** | ❌ 失败 | 显式依赖环，直接抛异常 |

→ 构造器 vs 字段阶段差异：[[20-依赖注入实现原理#构造器注入 DI 地图]]

## 六、AOP + 循环依赖

B 注入 A 时，若 A 需要代理，三级 factory 回调：

**`getEarlyBeanReference()`** — `AbstractAutowireCapableBeanFactory.java` L991–1000

```text
getEarlyBeanReference(beanName, mbd, rawBean)
  → AbstractAutoProxyCreator.getEarlyBeanReference()
       → wrapIfNecessary()          可能提前返回 A 的代理
```

A 在 `initializeBean` 末尾：

```text
postProcessAfterInitialization()
  earlyBeanReferences.remove(cacheKey) == bean
  → 已在早期代理过，不再重复 wrap
```

### 不一致风险

若早期注入的是 **raw A**，最终却是 **proxy A**，且依赖方已固定引用 raw 版 →  
`doCreateBean` L639–655 可能抛 `BeanCurrentlyInCreationException`。

- [[22-Spring-AOP代理创建详解#六、代理在 doCreateBean 中的三个时机]]

## 七、解决不了的情况（速查）

| 场景 | 现象 |
|------|------|
| `A(B b)` + `B(A a)` 构造器循环 | `BeanCurrentlyInCreationException` |
| Prototype 互引 | 创建检测失败 |
| `@DependsOn` 双向 | `Circular depends-on relationship` |
| `allowCircularReferences=false` | 不注册 factory，行为类似无法解决 |

Spring 官方建议：**不要依赖循环引用**，能改设计就改。

---

## 八、缓存生命周期

```text
创建 A 实例后：
  singletonFactories["a"] = ObjectFactory

B 需要 A，getSingleton("a")：
  factory.getObject() → earlySingletonObjects["a"] = 早期 A
  删除 singletonFactories["a"]

A 全部完成：
  singletonObjects["a"] = 成品 A
  清理 earlySingletonObjects["a"]
```

## 十一、常见面试题

| 问题 | 答案 |
|------|------|
| 三级缓存分别存什么？ | 一级成品、二级早期引用、三级 ObjectFactory |
| 为什么需要三级，二级不够吗？ | 三级存 **factory**，延迟 `getEarlyBeanReference`（含 AOP 决策），避免过早固定对象 |
| 构造器循环为什么不行？ | 实例化阶段就要依赖，尚无对象可暴露 |
| 字段循环为什么可以？ | 先 new 空壳 → 入三级 → populate 时再要依赖 |
| `@Lazy` 能打破循环吗？ | 注入代理，用时再创建，间接缓解 |

---

## 十二、记忆口诀

```text
Singleton 字段循环  → 三级缓存 + early reference
构造器循环          → 直接挂
Prototype 循环      → 直接挂
populate 之前       → 必须先 addSingletonFactory
AOP 循环              → getEarlyBeanReference 可能提前代理
```
