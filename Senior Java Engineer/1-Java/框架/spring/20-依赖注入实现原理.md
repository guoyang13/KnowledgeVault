## 一句话

Spring 的 DI 本质是：**在 Bean 创建过程中，容器根据类型/名称从工厂里找到依赖 Bean，再塞进目标对象**。核心发生在 `doCreateBean()` 的 **实例化之后、初始化之前**。

---

## 在 Bean 创建链路的哪一步

```text
getBean(name)
  → doGetBean()
    → createBean()
      → doCreateBean()
          ├── 1. createBeanInstance()     ← 实例化（构造器注入在这）
          ├── 2. populateBean()           ← 属性/字段/方法注入 ★ DI 主战场
          └── 3. initializeBean()         ← init-method、BPP 回调
```

| 步骤                     | DI 相关                  |
| ---------------------- | ---------------------- |
| `createBeanInstance()` | **构造器注入**              |
| `populateBean()`       | **字段 / Setter / 方法注入** |
| `initializeBean()`     | 初始化回调，不是注入本身           |

详见 [[17-Bean加载原理与源码阅读路径]]、[[09-容器层-BeanFactory与Registry详解#1.5 Bean 生命周期（BeanFactory 定义的标准顺序）]]。

## 三种注入方式的实现

| 方式 | 触发点 | 谁干活 |
|------|--------|--------|
| **构造器注入** | `createBeanInstance()` | `ConstructorResolver.autowireConstructor()` |
| **字段注入** `@Autowired` | `populateBean()` | `AutowiredAnnotationBeanPostProcessor` |
| **Setter / 方法注入** `@Autowired` | `populateBean()` | 同上 |
| **XML autowire** | `populateBean()` | `autowireByName()` / `autowireByType()` |

### 1. 构造器注入

```java
@Service
public class UserService {
    private final UserRepository repo;
    public UserService(UserRepository repo) {
        this.repo = repo;
    }
}
```

```text
createBeanInstance()
  → determineConstructorsFromBeanPostProcessors()
       AutowiredAnnotationBeanPostProcessor.determineCandidateConstructors()
  → autowireConstructor(beanName, mbd, ctors, args)
      → createArgumentArray()                    每个构造器参数
          → resolveAutowiredArgument()
              → beanFactory.resolveDependency()  ★ 与字段注入同一套
      → instantiate(constructor, args)           反射 new
```

→ **构造器注入完整 DI 地图**见下文「构造器注入 DI 地图」章节。

### 2. 字段 / 方法注入（@Autowired）

```java
@Service
public class OrderService {
    @Autowired
    private PaymentService paymentService;
}
```

```text
populateBean()
  → InstantiationAwareBeanPostProcessor.postProcessProperties()  ★
      → AutowiredAnnotationBeanPostProcessor.postProcessProperties()
          → 扫描 @Autowired / @Value / @Inject 字段和方法
          → metadata.inject(bean, beanName, pvs)
              → AutowiredFieldElement.inject()
                  → resolveFieldValue()
                      → beanFactory.resolveDependency(desc, ...)
                  → field.set(bean, value)   ← 反射赋值
```

关键源码（`AutowiredAnnotationBeanPostProcessor.java` L506-517）：

```java
public PropertyValues postProcessProperties(PropertyValues pvs, Object bean, String beanName) {
    InjectionMetadata metadata = findAutowiringMetadata(beanName, bean.getClass(), pvs);
    metadata.inject(bean, beanName, pvs);
    return pvs;
}
```

字段注入最终（L784）：

```java
value = beanFactory.resolveDependency(desc, beanName, autowiredBeanNames, typeConverter);
field.set(bean, value);
```

→ **字段 @Autowired 发生在哪里？** 见下文「@Autowired 注入发生在哪里」章节。

## 除 @Autowired 外的注入方式

Spring DI 不只 `@Autowired`，可按下表理解（**底层大多汇聚到 `resolveDependency()`**）：

| 类别 | 方式 | 触发点 | 处理者 |
|------|------|--------|--------|
| **注解** | `@Inject`（JSR-330） | 构造器 / 字段 / 方法 | `AutowiredAnnotationBeanPostProcessor` |
| **注解** | `@Resource`（JSR-250，**默认按名称**） | 字段 / Setter | `CommonAnnotationBeanPostProcessor` |
| **注解** | `@Value` / SpEL | 字段 / 方法 / 构造器参数 | `AutowiredAnnotationBeanPostProcessor` |
| **注解** | `@Bean` 方法参数 | 工厂方法实例化 | `instantiateUsingFactoryMethod()` → `resolveDependency()` |
| **XML** | `<property ref="..."/>` | `populateBean()` | `applyPropertyValues()` |
| **XML** | `autowire="byName|byType|constructor"` | 实例化 / populate | `autowireByName()` 等 |
| **Aware** | `ApplicationContextAware` 等 | `initializeBean()` | 容器回调（非注解 DI） |
| **延迟/可选** | `ObjectProvider<T>` / `Provider<T>` | 用时再 resolve | `doResolveDependency()` |
| **框架专用** | `@PersistenceContext` 等 | `populateBean()` | `PersistenceAnnotationBeanPostProcessor` |
| **编程式** | `autowireBean(existingObject)` | 手动调用 | `AutowireCapableBeanFactory` |

```text
Spring 依赖注入方式总览
├─ 注解：@Autowired / @Inject / @Resource / @Value / @Bean 参数
├─ XML：property / autowire
├─ Aware 回调
├─ ObjectProvider / @Lazy / Optional
└─ 编程式 autowireBean()
```

→ `@Resource` 与 `@Autowired` 差异：前者偏 **按 beanName**，后者偏 **按类型**（可配合 `@Qualifier`）。

## Spring 官方推荐哪种注入？

**推荐：构造器注入（Constructor Injection）**，用于 **必选依赖**。

| 优先级 | 方式 | Spring 态度 |
|:------:|------|-------------|
| **1** | **构造器注入** | ✅ 推荐 |
| 2 | Setter / 方法注入 | 可选依赖、可重配置时用 |
| 3 | 字段 `@Autowired` | ⚠️ 能用，不推荐 |

### 为什么推荐构造器？

| 理由 | 说明 |
|------|------|
| 依赖明确 | 构造器参数即必选依赖清单 |
| 不可变 | 字段可声明 `final` |
| 易测试 | `new Service(mockRepo)`，无需容器 |
| 避免半成品 | 实例出来依赖已齐；字段注入在 populate 前可能为 null |
| 不鼓励循环依赖 | 构造器循环依赖直接失败，逼你改设计 |

### 单构造器可省略 `@Autowired`

Spring 4.3+：**类只有一个构造器时，即使不加 `@Autowired` 也会用于注入**（见 `Autowired.java` javadoc）。

```java
@Service
public class OrderService {
    private final UserRepository repo;

    // 单构造器，无需 @Autowired
    public OrderService(UserRepository repo) {
        this.repo = repo;
    }
}
```

### 字段注入为何不推荐？

- 难单元测试（要容器或反射）
- 依赖 hidden，类签名看不出强依赖
- 不能 `final`
- Spring Boot / IDEA 常对 field injection 告警

### 可选依赖怎么写？

```java
// 方式 1：构造器 + ObjectProvider
public OrderService(UserRepository repo, ObjectProvider<CacheManager> cache) { ... }

// 方式 2：Setter + required=false
@Autowired(required = false)
public void setCacheManager(CacheManager cache) { ... }
```

→ 与 Aware 对比：业务依赖用 **构造器 DI（推式）**；Aware 只适合拿容器基础设施 → [[13-生命周期层-Aware体系详解]]

## `getBean(Class)` / `getBeanFactory().getBean(requiredType)` 链路

按类型获取 Bean **不是另一条创建路径**，而是 **先按类型解析 beanName，再汇入 `doGetBean(name, ...)`**。

```text
【Context 入口】
ctx.getBean(UserService.class)
  AbstractApplicationContext.getBean(Class)              L1451
    getBeanFactory().getBean(requiredType)
      │
      ▼
【DLBF — 按类型入口，实现在 DefaultListableBeanFactory，不在 AbstractBeanFactory】
DefaultListableBeanFactory.getBean(Class)                L425
  resolveBean(ResolvableType, args, false)
    resolveNamedBean(requiredType, args)                  ★ 类型 → 名字
      getBeanNamesForType(requiredType)                   扫描候选 beanName
      唯一 → getBean(beanName, null, args)
      多个 → @Primary / @Priority / 默认名 → 再 getBean(name)
      │
      ▼
【核心 — 与 getBean("name") 汇合】
AbstractBeanFactory.doGetBean(name, requiredType, args)  L250
  getSingleton(beanName)                                  缓存命中则直接返回
  未命中 → getMergedLocalBeanDefinition
         → depends-on → getBean(dep)
         → createBean() → doCreateBean()
  adaptBeanInstance(name, bean, requiredType)
```

### 两种 getBean 对比

| 调用 | 第一跳 | 如何定位 Bean |
|------|--------|---------------|
| `getBean("userService")` | 直接 `doGetBean` | 已有 name |
| `getBean(UserService.class)` | `resolveNamedBean` | **先按类型找 name**，再 `doGetBean` |

### 常见「找不到链路」的原因

1. 在 `AbstractBeanFactory` 搜 `getBean(Class)` — **没有**，实现在 **DLBF**
2. 单例已存在 — `doGetBean` 在 `getSingleton` 就返回，不进 `doCreateBean`
3. `@Autowired` 注入 — 走 `resolveDependency()` → 同样会到 `resolveNamedBean` / `doGetBean`，不是单独链路

→ `getBeanFactory()` 在 `GenericApplicationContext` 返回的就是 `DefaultListableBeanFactory` → [[09-容器层-BeanFactory与Registry详解]]、[[10-Context层-ApplicationContext详解]]

## 构造器注入 DI 地图

构造器注入发生在 **`doCreateBean()` 第 ① 步 `createBeanInstance()`**，早于字段注入。

```text
getBean("orderService")
  → doGetBean()
    → createBean() → doCreateBean()
      → createBeanInstance()                              ★ 入口
          │
          ├─ determineConstructorsFromBeanPostProcessors()
          │     AutowiredAnnotationBeanPostProcessor.determineCandidateConstructors()
          │       有 @Autowired 构造器 → 加入 candidates
          │       仅 1 个有参构造器 → 自动当作注入构造器（4.3+，可无 @Autowired）
          │
          └─ autowireConstructor()                        ★ 核心
                遍历候选构造器，选最匹配
                createArgumentArray()                     每个参数
                  resolveAutowiredArgument()
                    → resolveDependency()
                      → doResolveDependency()
                        → getBean(dependencyName)         依赖未创建则递归
                instantiate(constructor, args)            反射 new → rawBean
      → populateBean()                                    字段 @Autowired 在这之后
      → initializeBean()
```

### 构造器 vs 字段注入对比

| | 构造器注入 | 字段 / Setter `@Autowired` |
|--|-----------|---------------------------|
| **阶段** | `createBeanInstance()` | `populateBean()` |
| **BPP 回调** | `determineCandidateConstructors` | `postProcessProperties` |
| **核心类** | `ConstructorResolver` | `AutowiredAnnotationBeanPostProcessor` |
| **找依赖** | `resolveAutowiredArgument` → `resolveDependency` | 同上 |
| **赋值** | 构造器参数 | `field.set()` / setter 调用 |
| **循环依赖** | ❌ 通常失败 | ✅ 三级缓存 early reference |

### 构造器注入断点

| # | 类 · 方法 |
|:-:|-----------|
| 1 | `AbstractAutowireCapableBeanFactory.createBeanInstance()` |
| 2 | `AutowiredAnnotationBeanPostProcessor.determineCandidateConstructors()` |
| 3 | `ConstructorResolver.autowireConstructor()` |
| 4 | `ConstructorResolver.createArgumentArray()` |
| 5 | `DefaultListableBeanFactory.doResolveDependency()` |
| 6 | `ConstructorResolver.instantiate()` |

## @Autowired 注入发生在哪里？

### 字段 / Setter / 方法上的 `@Autowired`

**位置：** `populateBean()` → `AutowiredAnnotationBeanPostProcessor.postProcessProperties()`

```text
populateBean()
  └─ postProcessProperties()
       └─ AutowiredAnnotationBeanPostProcessor
            findAutowiringMetadata()          扫描 @Autowired / @Value / @Inject
            metadata.inject()
              AutowiredFieldElement.inject()
                resolveDependency() → field.set()
```

### 构造器上的 `@Autowired`

**位置：** `createBeanInstance()` → `autowireConstructor()`（见上节地图）

### 与 @PostConstruct、AOP 的顺序

```text
createBeanInstance()     构造器依赖已注入
populateBean()           ★ 字段 @Autowired
initializeBean()
  BeforeInit             @PostConstruct（可用已注入字段）
  AfterInit              AOP 代理
```

---

## 构造器 @Autowired 和字段 @Autowired 冲突吗？

**不冲突。** 两阶段 **先后执行**，不是二选一：

```text
① createBeanInstance()   构造器参数注入 + new
② populateBean()         字段 / Setter 再注入
```

| 场景 | 是否可行 |
|------|----------|
| 构造器注入必选依赖，字段注入其它依赖 | ✅ 可以 |
| 同一依赖构造器 + 字段各写一遍 | ⚠️ 不报错但冗余，别这么写 |
| 只有字段 @Autowired（隐式无参构造） | ✅ 常见 |
| 只有构造器注入（推荐） | ✅ 最佳 |

**最佳实践：** 必选依赖只走构造器；避免同一字段既写构造器参数又 `@Autowired`。

## 核心方法：`populateBean()`

`AbstractAutowireCapableBeanFactory.populateBean()`（L1403）是属性注入的总调度：

```text
populateBean(beanName, mbd, bw)
  ├── 1. InstantiationAwareBPP.postProcessAfterInstantiation()
  ├── 2. XML autowire（byName / byType）
  ├── 3. InstantiationAwareBPP.postProcessProperties()   ← @Autowired ★
  ├── 4. dependencyCheck
  └── 5. applyPropertyValues()                           ← XML property
```

日常注解开发，**第 3 步最关键** — `AutowiredAnnotationBeanPostProcessor` 实现了 `InstantiationAwareBeanPostProcessor`。

→ 详见 [[05-接口地图-IoC与DI重要接口大全#2.3 BeanPostProcessor — 上桌前品控加料 ★]]

## 核心方法：`resolveDependency()` — 找依赖 Bean

所有注入方式最终都汇聚到：

```text
resolveDependency(descriptor, requestingBeanName)
  → DefaultListableBeanFactory.doResolveDependency()
```

### doResolveDependency 决策链（L1722+）

```text
Step 1: 缓存 shortcut（已解析过的依赖）
Step 2: @Value → 从 Environment 取 "${server.port}"
Step 3: 按名称 / @Qualifier 精确匹配
Step 4a: 多 Bean → List / Map / 数组（@Autowired List<T>）
Step 4b: 按类型找候选 → findAutowireCandidates()
         → 多个候选 → @Primary / @Qualifier / @Priority 筛选
         → 唯一匹配 → getBean(dependencyName)
Step 4c: 找不到且 required=true → NoSuchBeanDefinitionException
```

简化版：

```text
需要什么类型？ → 容器里有哪些 Bean 匹配？
  → 0 个：报错或 optional（required=false / ObjectProvider）
  → 1 个：getBean 拿回来
  → 多个：@Primary → @Qualifier → NoUniqueBeanDefinitionException
```

**接口**：`AutowireCapableBeanFactory.resolveDependency()` — DI 最底层 API。

→ 详见 [[05-接口地图-IoC与DI重要接口大全#AutowireCapableBeanFactory — DI 最核心接口]]、[[08-注册层-BeanDefinitionRegistry与DefaultListableBeanFactory详解]]

## 参与 DI 的关键角色

```text
【扩展点】
  AutowiredAnnotationBeanPostProcessor   ← 识别 @Autowired/@Value，触发注入 ★
  CommonAnnotationBeanPostProcessor      ← @Resource、@PostConstruct

【容器】
  AbstractAutowireCapableBeanFactory     ← populateBean、autowireConstructor
  DefaultListableBeanFactory             ← doResolveDependency、候选筛选

【元数据】
  DependencyDescriptor                   ← 描述「需要注入什么」
  InjectionMetadata                      ← 缓存类的所有注入点

【候选筛选】
  AutowireCandidateResolver              ← @Qualifier、@Primary 判断
```

## 完整故事：OrderService 注入 PaymentService

```text
1. refresh() → preInstantiateSingletons()
2. getBean("orderService")
3. doCreateBean("orderService")
4. createBeanInstance()
     → new OrderService()（或 autowireConstructor 注入构造器参数）
5. populateBean()
     → AutowiredAnnotationBeanPostProcessor.postProcessProperties()
         → 发现字段 paymentService 有 @Autowired
         → resolveDependency(PaymentService.class, "orderService")
             → findAutowireCandidates() 找到 "paymentService"
             → getBean("paymentService")（未创建则递归创建）
         → field.set(orderService, paymentServiceInstance)
6. initializeBean() → @PostConstruct 等
7. OrderService 就绪
```

## 循环依赖与 DI

| 注入方式 | 循环依赖 |
|----------|---------|
| **构造器注入** | ❌ 无法解决（互相等对方先创建完） |
| **字段 / Setter 注入** | ✅ 三级缓存 early reference |

```text
A 创建中 → addSingletonFactory → 提前暴露到三级缓存
B 创建中 → getSingleton(A) → 拿到早期 A
A 继续完成 → B 注入完成
```

## @Value 注入

`@Value("${server.port}")` 不走 `getBean()`，在 `doResolveDependency` **Step 2**：

```text
getAutowireCandidateResolver().getSuggestedValue(descriptor)
  → resolveEmbeddedValue("${server.port}")
  → Environment.getProperty("server.port")
  → TypeConverter 转换类型
```

## 与 IoC 的关系

| 概念 | 在 DI 中的角色 |
|------|---------------|
| **IoC** | 思想：依赖不由自己 new，交给容器 |
| **DI** | 实现：容器在 populateBean / autowireConstructor 时「推」依赖 |
| **BeanDefinition** | 蓝图：记录 autowire 模式、property 值 |
| **BeanFactory** | 容器：提供 getBean() 和 resolveDependency() |

```text
IoC = 对象的命交给容器管
DI  = 容器把依赖塞给你（populateBean + resolveDependency）
```

## 常见面试题速答

| 问题 | 答案 |
|------|------|
| `@Autowired` 底层哪个方法？ | 字段：`populateBean` → `postProcessProperties` → `resolveDependency`；构造器：`createBeanInstance` → `autowireConstructor` |
| 构造器和字段 @Autowired 冲突吗？ | **不冲突**，先构造器后字段；同一依赖别写两遍 |
| 构造器和字段注入区别？ | 构造器在 createBeanInstance；字段在 populateBean |
| Spring 推荐哪种注入？ | **构造器注入**；单构造器可省略 `@Autowired` |
| 除了 @Autowired 还有哪些？ | `@Inject`、`@Resource`、`@Value`、XML、Aware、`ObjectProvider`、`@Bean` 参数等 |
| `getBean(Class)` 链路在哪？ | DLBF.resolveNamedBean → doGetBean（见上文地图） |
| 多个同类型 Bean 怎么选？ | @Primary → @Qualifier → @Priority → 报错 |
| `@Value` 怎么注入？ | doResolveDependency Step 2，从 Environment 取值 |
| 构造器循环依赖为什么失败？ | 实例化阶段互相等待，无法 early expose → [[21-循环依赖与三级缓存详解]] |
