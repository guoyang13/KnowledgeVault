# 配置类与组件类

> 导航：[[00-Spring-Bean加载-学习导航]] · **上篇 01–15** · 注解入门 · 专题入口

## 概念对照

| | **配置类（Configuration Class）** | **组件类（Component Class）** |
|---|---|---|
| 典型注解 | `@Configuration` | `@Component`、`@Service`、`@Repository`、`@Controller` |
| 一句话 | **装配容器**：定义有哪些 Bean、怎么组装 | **承载业务**：类本身就是应用逻辑 |
| 类比 | 导演 | 演员 |

---

## 共同点

1. **最终都会变成 Bean** — 注册 → `getBean()` → `doCreateBean()`
2. **都带 @Component 语义** — `@Configuration` meta-annotated `@Component`
3. **都支持依赖注入** — 构造器、`@Autowired`、`@Value`
4. **入口** — 显式 `register(Class)` 或包扫描 `scan()` / `@ComponentScan`，详见 [[07-元数据层-AnnotatedBeanDefinitionReader与组件注册详解]]
5. **生命周期一致** — 创建 → 注入 → 初始化 → 销毁

---

## 区别

| 维度 | 配置类 | 组件类 |
|------|--------|--------|
| **核心职责** | 定义容器结构 | 实现业务功能 |
| **是否解析 @Bean** | 是（主要用途） | 一般不这么用 |
| **能否 @ComponentScan** | 能 | 不能（除非自己再写） |
| **能否 @Import** | 能 | 不能 |
| **特殊处理器** | `ConfigurationClassPostProcessor` | 无 |
| **CGLIB 代理** | 默认会（Full 模式，见 [[22-Spring-AOP代理创建详解#二、两种「看起来像代理」的机制]]） | 不会（无 AOP Advisor 时） |
| **产出 Bean 数量** | 1 个配置类 + N 个 @Bean | 通常只有 1 个 |
| **典型包路径** | `config` | `service` / `dao` / `web` |

---

## 配置类做什么

**「装配图纸」** — 告诉容器里应该有什么、怎么连起来。

### 典型职责

1. **声明 Bean** — `@Bean` 注册第三方或无法扫描的类
2. **开启扫描** — `@ComponentScan`
3. **导入其他配置** — `@Import`
4. **加载外部配置** — `@PropertySource`
5. **条件装配** — `@Conditional` / `@Profile`
6. **开启框架能力** — `@EnableTransactionManagement` 等

### 示例

```java
@Configuration
@ComponentScan("com.example.service")
@EnableTransactionManagement
public class AppConfig {

    @Bean
    public DataSource dataSource() {
        return new HikariDataSource();
    }

    @Bean
    public PlatformTransactionManager txManager(DataSource ds) {
        return new DataSourceTransactionManager(ds);
    }
}
```

### 源码处理路径

```text
@ComponentScan / register(Class) 发现 @Configuration
  → AnnotatedBeanDefinitionReader.doRegisterBean（配置类本身）
  → refresh() 时 ConfigurationClassPostProcessor
      → ConfigurationClassParser 解析 @Import、@ComponentScan
      → ConfigurationClassBeanDefinitionReader 读取 @Bean
      → 再 registerBeanDefinition（更多 Bean）
```

> Reader / Scanner / @ComponentScan 三条注册路径 → [[07-元数据层-AnnotatedBeanDefinitionReader与组件注册详解]]

**配置类自己是一个 Bean，同时还是「Bean 工厂」。**

## 组件类做什么

**「这个类本身就是应用的一部分」** — Spring 只需创建并注入依赖。

### 典型职责

1. **实现业务逻辑**
2. **被其他 Bean 注入使用**
3. **表达分层语义** — `@Service` / `@Repository` / `@Controller`

### 示例

```java
@Service
public class UserService {

    private final UserRepository userRepository;

    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    public User findById(Long id) {
        return userRepository.findById(id);
    }
}
```

### 源码处理路径

```text
@ComponentScan / register(Class) 发现 @Service
  → registerBeanDefinition（只有这一个）
  → preInstantiateSingletons() → getBean() → doCreateBean()
```

> 组件类三条注册路径 → [[07-元数据层-AnnotatedBeanDefinitionReader与组件注册详解]]

**没有额外解析步骤，类本身 = 一个 Bean。**

> 没有 stereotype 注解的普通类不会被扫描，详见 [[100-Q&A/未被使用的类Spring如何处理]]。

## 关系图

```text
                    Spring 容器
                        │
         ┌──────────────┴──────────────┐
         │                             │
    配置类 (Configuration)        组件类 (Component)
    「装配中心」                   「业务单元」
         │                             │
    @Bean / @ComponentScan       @Service / @Repository
         │                             │
         └────────── 都注册为 ──────────┘
                    BeanDefinition → getBean() 创建实例
```

## 完整协作示例

```java
@Configuration
@ComponentScan("com.example")
public class AppConfig { }

@Repository
public class UserRepository {
    public User findById(Long id) { /* JDBC/JPA */ }
}

@Service
public class UserService {
    private final UserRepository repo;
    public UserService(UserRepository repo) { this.repo = repo; }
    public User getUser(Long id) { return repo.findById(id); }
}

@RestController
public class UserController {
    private final UserService service;
    public UserController(UserService service) { this.service = service; }
    @GetMapping("/users/{id}")
    public User getUser(@PathVariable Long id) { return service.getUser(id); }
}
```

### 启动时发生了什么

1. `AppConfig` 被扫描注册
2. `ConfigurationClassPostProcessor` 解析 `@ComponentScan`
3. 扫描并注册 `UserRepository`、`UserService`、`UserController`
4. 容器创建这些 Bean 并完成依赖注入

---

## 记忆口诀

- **配置类 = 导演**：决定舞台上有谁、怎么搭
- **组件类 = 演员**：上台后自己演业务

---

## 常见误区

| 误区 | 正解 |
|------|------|
| 有 `@Service` 就不需要 `@Configuration` | `@Service` 标记业务类，`@Configuration` 负责装配 |
| 在 `@Service` 里写 `@Bean` | 可以但不推荐，单例语义可能不对 |
| `@Service` 和 `@Component` 功能不同 | 对 Spring 几乎一样，只是语义分层 |
