## 一句话概括

**G1（Garbage-First）** 将堆切成 **等大小 Region**；逻辑仍分代，物理不连续。通过 **Young GC + 并发标记 + Mixed GC** 按 Region 增量回收，以 `MaxGCPauseMillis` 为软目标控制停顿，**优先收垃圾最多的 Old Region**。

# Part I：堆内存模型

## 1. G1 管理哪块内存

```text
线程共享
  Java 堆（-Xmx）     ← G1 管理对象分配与回收
  Metaspace           ← 类元数据，非 G1 堆内对象

线程私有：栈、PC（不在 G1 范围）
```

Metaspace 溢出需调 `MetaspaceSize`，**不能单靠 `-Xmx`**。

---

## 2. 与传统分代堆的区别

### 2.1 传统堆（Parallel / CMS）

```text
┌──────────── Young（连续）────────────┬──────────── Old（连续）────────────┐
│  Eden  │  S0  │  S1                   │  长期存活对象                      │
└──────────────────────────────────────┴──────────────────────────────────┘
```

- Young / Old **物理连续**，比例较固定（`NewRatio`、`-Xmn`）
- Old GC 常 **整代 STW**，堆越大停顿越长

### 2.2 G1 堆：Region 网格

```text
┌──E──┬──E──┬──S──┬──O──┬──H──┬──F──┬──O──┬──E──┐
  无「左 Young、右 Old」；E 与 O 可交错分布
```

| 维度 | 传统堆 | G1 |
|------|--------|-----|
| 基本单位 | 整代大块 | **Region**（等大小） |
| Young | 连续 Eden + S0/S1 | **E + S Region 集合** |
| Old | 连续一块 | **O + H Region 集合** |
| 比例 | 较固定 | **动态调整各类型 Region 个数** |

> **核心心智：分代是「角色集合」，不是「连续内存段」。**

---

## 3. Region 基础

```text
-Xmx = 4GB，Region = 4MB  →  约 1024 个 Region
Region 大小：2 的幂，约 1MB～32MB，通常 JVM 自动计算
```

```bash
-XX:G1HeapRegionSize=4m   # 一般无需手动指定
```

---

## 4. 五种 Region 角色

| 标记 | 类型 | 职责 |
|------|------|------|
| **E** | Eden | 新对象分配（经 TLAB） |
| **S** | Survivor | Young GC 后存活对象 |
| **O** | Old | 晋升后的老对象 |
| **H** | Humongous | 超大对象（> Region × 50%） |
| **F** | Free | **空 Region，待重新分配角色** |

**逻辑分代**：

```text
年轻代 = 所有 E Region + 所有 S Region
老年代 = 所有 O Region + 所有 H Region
```

**角色会流转**：`Free → E → GC 搬空 → Free → S → O → Mixed GC → Free → …`

---

## 5. Free Region

**Free = 整块空的 Region**，是 G1 的「空闲池」。

| Free 从哪来 | 说明 |
|-------------|------|
| 堆初始化 | 尚未分配角色的 Region |
| Young / Mixed GC | 复制后原 Region 被清空 |
| Cleanup | 完全无存活对象的 Old Region |

| Free 之后 | 说明 |
|-----------|------|
| 需要 Eden / Survivor / Old | 从 Free 取出，标为 E、S 或 O |

```text
堆使用率 ≈ (总 Region - Free Region) / 总 Region
Free 少 → 即将 GC；Free ≈ 0 → Evacuation Failure 风险
```

**勿混淆**：Free 是 **整 Region 为空**；TLAB 内空洞时 Region 仍是 E；`-Xms < -Xmx` 未提交内存不是 Free。

```text
    Free ──→ Eden / Survivor / Old
              └── GC 搬空 ──→ Free
```

---

## 6. 对象分配与 Humongous

> TLAB、refill、四种 GC 分配路径详见 [[1006-JVM内存分配]]。

### 6.1 普通对象

```text
new → TLAB（在某个 E Region 内）→ TLAB 满 → 申请 E Region
→ 所有 E 满 → Young GC
```

### 6.2 Humongous

```text
对象 > Region × 50%  →  占 1+ 个 H Region
不进 Survivor；语义上进老年代；Mixed / Full GC 回收
```

例：Region 4MB，对象 5MB → 2 个 H Region。

---

## 7. Young GC 前后堆的变化

```text
GC 前：  [E满][E满][S ]
GC 中：  复制存活 → 新 S 或 O Region（STW，CSet = 所有 E+S）
GC 后：  [F ][F ][S'][O ]   原 E/S 变 Free，再从 Free 分配新 E
```

- **复制算法**，Region 级无碎片
- 靠 **RSet** 扫描跨代引用，不扫整个 Old

---

## 8. 堆模型心智图

```text
                 G1 Heap (-Xmx)
┌────────────────────────────────────────────┐
│ [E] [E] [S] [O] [H] [F] [O] [E] ...        │
│  ↑TLAB      ↑RSet    ↑空闲池               │
└────────────────────────────────────────────┘
年轻代 = E+S 集合    老年代 = O+H 集合
```

### 年轻代参数（不用 -Xmn）

```bash
-XX:G1NewSizePercent=5
-XX:G1MaxNewSizePercent=60
# 实际年轻代 = 当前 (E+S) Region 数 × Region 大小，随 GC 动态变
```

### 常见误解

| 误解 | 事实 |
|------|------|
| G1 无分代 | 有，按 E+S / O+H 集合 |
| Eden 是一整块 | 多个 **E Region** |
| Old 在堆后半 | **O Region 散落** |
| Free = 碎片 | Free 是 **整 Region 粒度** 空闲 |

# Part II：回收机制

## 9. 总流程

```text
分配 → Eden Region 满
    → Young GC（STW）
    → 堆占用 ≥ IHOP → 并发标记周期
    → Mixed GC × N（STW，部分 Old + Young）
    → （极端）Evacuation Failure → Full GC（应避免）
```

G1 两个大阶段交替：

```text
Young-Only 阶段：多次 Young GC，对象逐渐进入 Old
Space-Reclamation 阶段：并发标记 + Mixed GC，增量收 Old
```

---

## 10. Young GC

| 项 | 说明 |
|----|------|
| 触发 | Eden Region 用尽 |
| 停顿 | STW |
| CSet | 所有 **E + S** Region |
| 算法 | 复制存活对象 → S 或 O；清空源 Region → **Free** |
| 晋升 | 年龄、`Survivor` 放不下、动态年龄判定等 |

---

## 11. 并发标记周期

**目的**：统计各 **O Region 垃圾比例**，供 Mixed GC 做 Garbage-First 选区。  
**不搬对象**；真正回收在 Mixed GC。

### 11.1 触发

```bash
-XX:InitiatingHeapOccupancyPercent=45   # 堆已用 ≥ 45% 启动（JDK 10+ 可自适应）
```

### 11.2 四阶段

| 阶段 | STW | 工作 |
|------|-----|------|
| **Initial Mark** | 短 | 标 GC Roots 直接可达；常搭 Young GC |
| **Concurrent Mark** | 并发 | 遍历对象图；统计 Region 存活率 |
| **Remark** | 短 | 处理 SATB / 脏卡，补齐标记 |
| **Cleanup** | 部分 | 选 Mixed 候选；完全空 O Region → **Free** |

```text
  │◄IM►│◄──── Concurrent Mark ────►│◄Rmk►│Cleanup│ → Mixed GC × N
```

### 11.3 SATB

```text
标记开始时存活 → 本周期视为存活
标记期间新引用 → 也当存活（宁可多标，不漏标）
写引用 → Pre-Write Barrier 记 SATB 缓冲 → Remark 处理
```

代价：浮动垃圾（下周期再收）。

---

## 12. Mixed GC

| 项 | 说明 |
|----|------|
| 触发 | 并发标记完成 |
| 停顿 | STW |
| CSet | 所有 Young Region + **垃圾最多的若干 O Region** |
| 特点 | 多轮增量收 Old，非整代；CSet 大小受 `MaxGCPauseMillis` 约束 |

**Garbage-First**：Cleanup 后按 Region 垃圾比例排序，优先收收益最高的 O Region。

---

## 13. Full GC

| 项 | 说明 |
|----|------|
| 触发 | Evacuation Failure（复制时无目标 Region）、极端压力 |
| 过程 | 通常单线程整堆 STW |
| 对策 | 增大堆、放宽停顿目标、查泄漏、保证 Mixed 跟得上分配 |

---

# Part III：底层支撑

## 14. RSet、Card Table、CSet

### 14.1 Remembered Set（RSet）

每个 Region（尤其 O）记录 **「哪些其他 Region 引用了我」**。

```text
Young GC：只扫相关 RSet，不扫整个 Old
Region = 空间单元 + GC 记账单元
```

维护代价：写引用时的写屏障。

### 14.2 Card Table

记录跨 Region / 跨代引用，配合 RSet 与 Remark 处理脏卡。

### 14.3 Collection Set（CSet）

每次 GC 实际回收的 Region 集合：

```text
Young GC：所有 E + S
Mixed GC：所有 Young + 部分 O（垃圾多的）
```

G1 根据历史 GC 耗时预测，调整 CSet 大小以逼近停顿目标。

### 14.4 MaxGCPauseMillis

```bash
-XX:MaxGCPauseMillis=200   # 软目标，非硬保证
```

过激进 → Mixed 过频或 Evacuation Failure。

# Part IV：运维与对比

## 15. 对象一生（串联堆模型与 GC）

```text
1. new → E Region（TLAB）
2. E 满 → Young GC → 存活进 S 或 O，空 Region 变 Free
3. 多次 Young GC → 晋升 O Region；大对象进 H
4. 堆 ≥ IHOP → 并发标记（摸底 O Region 垃圾）
5. Mixed GC → 收 Young + 最空的 O Region → 释放 Free
6. 循环；失败则 Full GC
```

---

## 16. 与其他 GC 对比

| 维度 | Parallel | CMS | **G1** | ZGC |
|------|----------|-----|--------|-----|
| JDK 默认 | 8 服务端 | 已移除(14) | **9+** | 需显式开启 |
| 堆布局 | 连续分代 | 连续分代 | **Region** | Page |
| Old 回收 | 整代 STW 整理 | 并发清除，碎片 | **Mixed 部分 Region** | 并发整理 |
| 停顿 | 随堆变差 | 较短但有碎片 | **可设目标 ~200ms** | 亚毫秒级 |
| 吞吐 | 最高 | 中 | 中 | 较低（分代后↑） |

ZGC 专题见 [[1005-ZGC垃圾回收与堆内存]]。

## 17. 常用参数

| 参数 | 含义 | 建议 |
|------|------|------|
| `-XX:+UseG1GC` | 启用 G1 | JDK 9+ 默认 |
| `-Xms` / `-Xmx` | 堆大小 | 生产常相等 |
| `-XX:MaxGCPauseMillis` | 停顿目标 ms | 200 |

| `-XX:InitiatingHeapOccupancyPercent` | 触发并发标记% | 45 |
| `-XX:G1NewSizePercent` / `G1MaxNewSizePercent` | 年轻代占比范围 | 5 / 60 |
| `-XX:MaxTenuringThreshold` | 晋升年龄 | 15 |
| `-XX:G1ReservePercent` | 预留防 evacuation 失败 | 10 |

## 18. GC 日志与排查

```bash
-Xlog:gc*:file=gc.log:time,uptime,level,tags
```

| 日志关键词 | 含义 |
|------------|------|
| `Pause Young (Concurrent Start)` | Initial Mark |
| `Concurrent Mark` | 并发标记 |
| `Pause Remark` | Remark STW |
| `Pause Cleanup` | Cleanup STW |
| `Mixed GC` | Mixed 回收 |

| 现象 | 可能原因 |
|------|----------|
| Mixed 少、Old 涨 | IHOP 高、堆小、分配快 |
| Remark 长 | 引用变动大、SATB 多 |
| Full GC | evacuation 失败、泄漏、堆过小 |

详细排查流程见 **Part V §25**。

## 19. 面试速记

1. G1 堆 = **等大小 Region**；年轻代 = E+S，老年代 = O+H；**物理不连续**。
2. **Free**：GC 搬空后的空 Region；从 Free 池再分配 E/S/O。
3. **Humongous**：> Region 50%，占 H Region。
4. **Young GC**：CSet = 所有 E+S，复制 evacuation，源区变 Free。
5. **并发标记**：IM → CM → Remark → Cleanup；只摸底，不搬对象。
6. **SATB + RSet**：并发标记防漏标；Young GC 不扫整个 Old。
7. **Mixed GC**：Young + 垃圾最多的 O Region（Garbage-First）。
8. **Full GC**：evacuation 失败，应避免。
9. 年轻代用 `G1NewSizePercent`，**不是** `-Xmn`。
10. Metaspace 与堆分开配置。
11. 工程实践：`-Xms=-Xmx`、必开 GC 日志、盯 Full GC；详见 **Part V**。

# Part V：工程实践

> 面向 JDK 9+ 默认 G1 的生产配置、观测与排查。与 Part IV 参数表、日志关键词互补。

## 21. 堆内存怎么设

### 21.1 基本原则

| 做法 | 原因 |
|------|------|
| **`-Xms = -Xmx`** | 避免堆动态扩缩带来的 GC 波动和额外开销 |
| **容器留 OS 余量** | 不要 `-Xmx` 顶满 cgroup limit，建议 **70%～75%** |
| **Metaspace 单独配** | 堆 OOM ≠ Metaspace OOM，不能单靠 `-Xmx` |

```bash
-Xms4g -Xmx4g
-XX:MetaspaceSize=256m
-XX:MaxMetaspaceSize=512m
```

### 21.2 堆多大合适

```text
1. 压测 / 灰度峰值堆占用 × 1.5～2（留 Mixed GC 和 Humongous 空间）
2. 容器 limit 8G → -Xmx 约 5～6G
3. 过小 → Mixed 跟不上、Evacuation Failure、Full GC
4. 过大 → Remark 变长、单次 Mixed 仍可控但摸底成本高
```

| 应用规模 | 常见 -Xmx |
|----------|-----------|
| 小型 Web | 2～4G |
| 中型 | 4～8G |
| 大型 | 8～16G+ |

G1 适合 **4G～几十 G**；极小堆（<512M）可考虑 Serial；极低延迟 + 超大堆可评估 [[1005-ZGC垃圾回收与堆内存|ZGC]]。

### 21.3 不要用的参数

```text
❌ -Xmn / -XX:NewRatio     # G1 不用传统切代，用 G1NewSizePercent
❌ -XX:+UseConcMarkSweepGC # CMS 已移除
❌ 只设 -Xmx 不设 -Xms     # 生产尽量相等
```

## 22. 生产推荐配置与调参

### 22.1 起步配置（4～8G 堆 Web 服务）

```bash
-XX:+UseG1GC
-Xms4g -Xmx4g
-XX:MaxGCPauseMillis=200
-XX:InitiatingHeapOccupancyPercent=45
-XX:G1ReservePercent=10
-XX:G1NewSizePercent=5
-XX:G1MaxNewSizePercent=40
-XX:MaxTenuringThreshold=15
```

### 22.2 调参方向

| 参数 | 默认 | 调优方向 |
|------|------|----------|
| `MaxGCPauseMillis` | 200 | RT 敏感试 **100～150**；吞吐优先 **300～400**。过小 → Mixed 过频、evacuation 风险 |
| `InitiatingHeapOccupancyPercent` | 45 | Old 涨得快 → **降到 35～40**；Mixed 太频繁 → 略提高 |
| `G1ReservePercent` | 10 | evacuation 失败多 → 保持 10，**优先加大堆** |
| `G1MaxNewSizePercent` | 60 | 分配快 / Young GC 过频 → 适当提高；停顿长 → 略降 |
| `G1HeapRegionSize` | 自动 | Humongous 过多 → 可适当增大 Region（减少 H 区数量） |

### 22.3 JDK 10+ Adaptive IHOP

```text
默认根据 GC 历史自动调整 IHOP
若 Mixed 总是偏晚 / 偏早，再手动覆盖 InitiatingHeapOccupancyPercent
```

## 23. 可观测性

### 23.1 GC 日志（JDK 9+）

```bash
-Xlog:gc*,gc+age=trace:file=gc.log:time,uptime,level,tags:filecount=5,filesize=50m
```

JDK 8：

```bash
-XX:+PrintGCDetails -XX:+PrintGCDateStamps -XX:+PrintGCTimeStamps
-Xloggc:/path/gc.log -XX:+UseGCLogFileRotation -XX:NumberOfGCLogFiles=5 -XX:GCLogFileSize=50M
```

### 23.2 建议监控指标

| 指标 | 健康参考 | 告警信号 |
|------|----------|----------|
| Young GC 频率 | 稳定、可预期 | 突然暴增（分配泄漏 / 流量 spike） |
| Young GC 停顿 | 一般 <50ms（视堆） | 持续 >100ms |
| Mixed GC 频率 | 并发标记后周期性出现 | 几乎没有、Old 一直涨 |
| **Full GC 次数** | **0 或极少** | **出现即高危** |
| Remark 停顿 | 通常较短 | 频繁 >500ms |
| 堆使用率 | 锯齿状回落 | 只升不降（泄漏） |
| Humongous 分配 | 偶发 | 持续大量（大对象问题） |

### 23.3 常用工具

| 工具 | 用途 |
|------|------|
| **GCeasy / GCEasy** | 上传 gc.log 自动分析 |
| **jcmd** | `GC.heap_info`、`VM.native_memory` |
| **Micrometer + Prometheus** | JVM 内存、GC 暂停 |
| **Arthas / JFR** | 分配热点、大对象（`-XX:StartFlightRecording`） |

## 24. 日志解读与危险信号

### 24.1 正常 G1 节奏

```text
Pause Young (Normal)              # 常规 Young GC
Pause Young (Concurrent Start)    # 搭 Initial Mark
Concurrent Mark
Pause Remark
Pause Cleanup
Pause Young (Mixed)               # Mixed GC
```

### 24.2 危险信号

| 日志 / 现象 | 含义 |
|-------------|------|
| `Pause Full (G1 Evacuation Failure)` | 复制没目标区，堆或调优有问题 |
| `to-space exhausted` | 同 evacuation failure |
| 只有 Young、长期无 Mixed | IHOP 太高或并发标记未完成 |
| Remark 极长 | 堆大、引用变动剧烈、根集合大 |
| `humongous` 频繁 | 大数组 / 大 JSON / 大缓存 |

## 25. 问题排查手册

### 25.1 出现 Full GC

```text
排查顺序：
1. gc.log 找 Full GC 前是否 Evacuation Failure
2. 堆是否过小（-Xmx 相对峰值占用）
3. MaxGCPauseMillis 是否过激进（如 50ms）
4. 是否有内存泄漏（堆 Used 只升不降）
5. Humongous 是否过多挤占 Region
6. Mixed GC 是否长期不执行
```

**处理**：增大 `-Xmx`（保持 `-Xms=-Xmx`）；放宽 `MaxGCPauseMillis` 到 200～300；IHOP 降到 35～40；查分配热点与泄漏。

### 25.2 Old 一直涨、Mixed 很少

```text
可能原因：IHOP 太高；分配速率 > 回收速率；晋升过快
```

```bash
-XX:InitiatingHeapOccupancyPercent=35
-XX:G1MaxNewSizePercent=40
```

结合 **heap dump** 看 Old 里是谁在涨。

### 25.3 Young GC 太频繁

```text
原因：分配太快 或 年轻代偏小
```

提高 `G1MaxNewSizePercent`；查短生命周期大对象（日志序列化、临时 List）；业务限流 / 批处理改流式。

### 25.4 Young GC 停顿过长

```text
原因：单次 CSet 内对象多、RSet 扫描大、根集合大
```

略降 `G1MaxNewSizePercent`；查 Humongous、减少大对象；检查跨 Region 引用。

### 25.5 Remark 停顿长

减少不必要的引用变更（缓存结构）；堆实在过大考虑 [[1005-ZGC垃圾回收与堆内存|ZGC]]。

### 25.6 RT 抖动 / P99 尖刺

```text
1. gc.log 对齐尖刺时间点 → 是否 Mixed / Remark
2. MaxGCPauseMillis 从 200 试 150
3. 避免与业务高峰重叠的批量任务
4. 仍不满意 → 压测 [[1005-ZGC垃圾回收与堆内存|ZGC]] 对比
```

### 25.7 Metaspace OOM

```text
java.lang.OutOfMemoryError: Metaspace
```

查 **类加载泄漏**（动态代理、Groovy、热部署、ClassLoader 泄漏）；调 `MaxMetaspaceSize`。

## 28. 何时考虑换 ZGC

详见 [[1005-ZGC垃圾回收与堆内存]] §16 选型指南。

```text
✅ 仍用 G1：通用 Web、4～16G、200ms 级停顿可接受
✅ 评估 ZGC：
   - P99 要求极高（<10ms GC 贡献）
   - 堆 ≥16G 且 Remark/Mixed 仍不满意
   - JDK 21+ 可分代 ZGC，吞吐损失比早期 ZGC 小
```

## 29. 发布检查清单

```text
□ -Xms = -Xmx
□ 容器 limit 与 -Xmx 留余量
□ Metaspace 上限已设
□ GC 日志已开启并轮转
□ 监控：堆、GC 暂停、Full GC 次数
□ 压测覆盖峰值流量
□ 无 Full GC / Evacuation Failure
□ Mixed GC 周期性出现、堆呈锯齿
```

### 实战一句话

> **G1 工程实践：`-Xms=-Xmx`、容器留余量、默认 `MaxGCPauseMillis=200` + IHOP 45、必开 GC 日志；排查盯 Full GC 和 Evacuation Failure，Old 涨调 IHOP，停顿尖刺看 Mixed/Remark，大对象查 Humongous。**
