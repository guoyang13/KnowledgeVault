## 一句话概括

**零拷贝**不是「完全不拷贝」，而是**避免数据在内核与用户空间之间不必要的 CPU 拷贝**，让数据尽量在内核里从 Page Cache 直达 Socket/NIC。

---

# Part I：问题与目标

## 1. 传统 read + write 路径

```text
磁盘 ──DMA──> 内核 Page Cache ──CPU──> 用户 Buffer ──CPU──> Socket Buffer ──DMA──> 网卡
                              ↑ 2 次 CPU 拷贝 + 4 次上下文切换（典型）
```

## 2. 零拷贝目标

- 减少 CPU 参与的内存拷贝
- 减少用户态/内核态切换
- 适合：静态文件服务、MQ 日志发送、大文件传输

---

# Part II：实现方式

## 1. Linux sendfile

内核直接把文件描述符数据送到 socket fd，用户态不参与数据拷贝。

```text
磁盘 ──DMA──> Page Cache ──CPU/DMA──> Socket ──DMA──> 网卡
                    （用户态不碰数据）
```

Linux 2.4+ 配合 scatter-gather 可进一步减少 CPU 拷贝（仅传 buffer 描述符）。

## 2. Java NIO 入口

| API | 底层 | 说明 |
|-----|------|------|
| `FileChannel.transferTo()` | `sendfile`（Linux） | 文件 → Socket，最接近零拷贝 |
| `FileChannel.map()` | `mmap` | 文件映射到堆外地址，减少显式 read |
| `SocketChannel.write(DirectBuffer)` | `write` | 堆外→内核仍有一次拷贝，但省「堆→堆外」 |

```java
try (FileChannel in = FileChannel.open(path, StandardOpenOption.READ)) {
    WritableByteChannel out = Channels.newChannel(socket.getOutputStream());
    in.transferTo(0, in.size(), out);
}
```

## 3. Netty DefaultFileRegion

Netty 封装 `transferTo`，Epoll 传输层在 Linux 上走 `sendfile`。

## 4. mmap 与零拷贝的关系

`MappedByteBuffer` 把文件页映射进进程地址空间，读写像访问内存；发到网络时若仍用 `write`，内核侧还有一次拷贝。RocketMQ CommitLog、Kafka 日志段常用 **mmap + 顺序写** 提升写盘性能。

# Part III：工程实践

| 组件 | 用法 |
|------|------|
| **Kafka** | 消费发送：`mmap` + `write` / `transferTo` |
| **RocketMQ** | CommitLog `mmap` 写盘；消费路径减少拷贝 |
| **Nginx** | 静态资源 `sendfile` |
| **Netty** | `FileRegion` 发文件 |
