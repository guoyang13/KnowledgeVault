## 一句话概括

**ZGC（Z Garbage Collector）** 以 **染色指针 + 读屏障 + 并发 relocation** 实现 **亚毫秒级 STW**，停顿几乎不随堆增大而线性恶化；JDK 21+ **分代 ZGC** 在保留低延迟的同时显著提升吞吐，JDK 23 起开启 ZGC 默认走分代模式。

---

# Part I：堆内存模型

## 1. ZGC 管理哪块内存

```text
线程共享
  Java 堆（-Xmx）     ← ZGC 管理对象分配与回收
  Metaspace           ← 类元数据，非 ZGC 堆内对象

线程私有：栈、PC（不在 ZGC 范围）
```

Metaspace 溢出需单独调 `MetaspaceSize`，**不能单靠 `-Xmx`**。

---

## 2. 与 G1 Region 的区别

G1 将堆切成 **等大小 Region**（见 [[1004-G1垃圾回收与堆内存]]）。ZGC 用 **Page（页）** 按对象大小分级管理：

```text
ZGC Heap
├── Small Page（2MB）    → 普通小对象
├── Medium Page（32MB）  → 中等对象
└── Large Page           → 超大对象，独占一页或多页
```

| 维度 | G1 | ZGC |
|------|-----|-----|
| 基本单位 | 等大小 Region | **按对象大小分级的 Page** |
| 大对象 | Humongous Region（> Region × 50%） | **Large Page** |
| 物理布局 | E/S/O 散落 | Page 集合 |
| 碎片 | Region 内复制，较少 | **页级并发整理，基本无碎片** |

> **核心心智：ZGC 不是 Region 网格，而是大小分级的页式堆。**

---

## 3. 对象分配

> TLAB、各回收器分配路径详见 [[1006-JVM内存分配]] §9。

```text
new 小对象  → Small Page（经 TLAB）
new 中对象  → Medium Page
new 大对象  → Large Page（独占）
Page 用尽 / 分配压力  → 触发 GC
```

分代 ZGC 下，新对象先进 **年轻代 Page**；存活对象晋升 **老年代 Page**。

---

## 4. 堆模型心智图

```text
                 ZGC Heap (-Xmx)
┌────────────────────────────────────────────────┐
│ [Small][Small][Medium][Large][Small] ...       │
│   ↑年轻代 Page          ↑老年代 Page            │
│   读屏障在每次 load 引用时介入                   │
└────────────────────────────────────────────────┘
```

# Part II：核心技术

ZGC 能 **并发移动对象** 且 STW 极短，依赖三项技术。

## 5. 染色指针（Colored Pointers）

64 位指针中，高位用于编码 **GC 状态**（Marked0 / Marked1 / Remapped / Finalizable 等），低位仍是对象地址：

```text
指针 = 地址位 + GC 颜色位
```

| 作用 | 说明 |
|------|------|
| 存活状态 | 对象是否被本周期标记，编码在指针里 |
| 并发移动 | 对象从 A 搬到 B 后，旧指针仍可能带「过期颜色」 |
| 延迟更新 | 不必 STW 立刻更新全堆所有引用 |

利用 64 位虚拟地址空间远大于实际物理内存，在指针中「藏」元数据。

---

## 6. 读屏障（Load Barrier）

应用线程 **每次从堆读引用** 时，JVM 插入极轻量逻辑：

```text
线程读引用 ptr
  → 检查 ptr 颜色是否过期
  → 若过期：修正为最新地址（或协助标记）
  → 返回正确引用
```

| GC | 屏障类型 | 触发时机 |
|----|----------|----------|
| G1 | **写屏障** | 写引用时 |
| ZGC | **读屏障** | **读引用时** |

写屏障影响「写」路径；读屏障影响「读」路径。ZGC 选择读屏障配合染色指针，更适合 **并发 relocation**。

---

## 7. 多重映射（Multi-Mapping）

同一物理内存可映射到多个虚拟地址视图，配合染色指针：

```text
对象从地址 A 搬到 B
  旧指针仍可能指向 A 的「染色视图」
  读屏障发现过期 → 重定向到 B
  最终一致，无需长时间 STW 更新全堆引用
```

---

## 8. 三项技术串联

```text
染色指针  →  记录对象 GC 状态，支持并发移动
读屏障    →  应用线程读引用时自动修正过期指针
多重映射  →  虚拟地址视图切换，降低 relocation 的 STW 成本
```

# Part III：回收机制

## 9. 设计目标

| 目标 | 说明 |
|------|------|
| **超低停顿** | 目标 < 1ms，常见 1～3ms（视负载） |
| **可扩展** | 堆几百 MB ～ **16TB**，停顿不随堆线性恶化 |
| **并发为主** | 标记、整理、移动均在应用运行时进行 |
| **无碎片** | 并发 relocation 压缩，不像 CMS 碎片累积 |

代价：**吞吐通常低于 Parallel / G1**（屏障与并发 CPU 开销）；分代 ZGC 显著改善。

---

## 10. 版本演进

```bash
-XX:+UseZGC
```

| 版本 | 里程碑 |
|------|--------|
| JDK 11 | 实验性引入 |
| JDK 15 | 生产可用（转正） |
| JDK 17 LTS | 较成熟 |
| JDK 21 | **分代 ZGC（Generational ZGC）** |
| JDK 23 | 开启 ZGC 时 **默认分代模式**（[JEP 474](https://openjdk.org/jeps/474)） |

```bash
-XX:+UseZGC              # JDK 23+ 默认分代
-XX:-ZGenerational       # 关闭分代（特殊场景）
```

## 11. 完整 GC 周期（非分代底模）

ZGC 一次完整周期只有 **3 个 STW 点**，其余并发：

```text
Pause Mark Start        （极短 STW）
Concurrent Mark         （并发标记存活对象）
Pause Mark End          （极短 STW）
Concurrent Process References  （弱/软/虚引用等）
Concurrent Reset / Prepare
Concurrent Select Relocation Set  （选要搬空的 Page）
Pause Relocate Start    （极短 STW）
Concurrent Relocate     （并发移动存活对象，释放旧 Page）
```

### 11.1 各阶段

| 阶段 | STW? | 工作 |
|------|------|------|
| **Mark Start** | 短 | 开始新一轮标记，处理根集合 |
| **Concurrent Mark** | 否 | 遍历对象图，标记存活 |
| **Mark End** | 短 | 结束标记，处理并发期间变动 |
| **Select Relocation Set** | 否 | 选垃圾多的 Page 作为搬迁源 |
| **Relocate Start** | 短 | 开始并发移动 |
| **Concurrent Relocate** | 否 | 存活对象复制到新 Page，旧 Page 释放 |

### 11.2 与 G1 对比

| | G1 | ZGC |
|--|-----|-----|
| 移动对象 | Young/Mixed 时 **STW 复制** | **并发 relocation** |
| 标记 | 并发标记 + Remark STW | 并发标记 + 极短 Mark End |
| 碎片 | Region 复制 | 页级并发整理 |
| 停顿来源 | Young/Mixed/Remark 可能较长 | 几乎只剩极短 pause |

---

## 12. SATB 与漏标

并发标记期间应用线程仍在运行。ZGC 用 **SATB（Snapshot-At-The-Beginning）**：

```text
标记开始那一刻已存在的引用链 → 本轮视为存活
标记期间新产生的引用 → 也当存活（宁可多标，不能漏标）
```

代价：浮动垃圾（下周期再收）。

---

## 13. 分代 ZGC（Generational ZGC）

JDK 21+ 最重要演进。

### 13.1 为什么需要分代

早期 ZGC **不分代**：

```text
每次 GC 周期 ≈ 扫全堆
→ CPU 开销大，吞吐明显低于 G1
→ 适合「极低延迟 + 大堆」，不适合高吞吐通用 Web
```

分代 ZGC 引入年轻代 / 老年代：

```text
大部分对象朝生夕死
  → 高频、轻量收年轻代
老年代
  → 较低频率走完整 ZGC 周期（标记 + relocation）
```

效果：停顿仍亚毫秒～低毫秒；**吞吐接近 G1**；JDK 23 默认分代成为「正常打开方式」。

### 13.2 分代节奏

```text
对象分配 → 年轻代 Page
  → 年轻代 GC（频繁、停顿极短）
  → 存活晋升老年代
  → 老年代积累到阈值
  → 完整 ZGC 周期（并发标记 + relocation）
```

---

## 14. 周期总图

```text
                    ZGC 一次完整周期
┌─────────────────────────────────────────────────────────┐
│  STW: Mark Start（极短）                                 │
│    ↓                                                    │
│  并发: Mark ──→ 标记存活（SATB）                         │
│    ↓                                                    │
│  STW: Mark End（极短）                                   │
│    ↓                                                    │
│  并发: Select Relocation Set ──→ 选垃圾多的 Page          │
│    ↓                                                    │
│  STW: Relocate Start（极短）                             │
│    ↓                                                    │
│  并发: Relocate ──→ 存活对象搬到新 Page，释放旧 Page     │
│         ↑                                               │
│    应用线程读引用：Load Barrier 修正染色指针              │
└─────────────────────────────────────────────────────────┘

分代 ZGC：年轻代频繁轻量回收 + 老年代周期性完整周期
```

# Part IV：运维与对比

## 15. 与其他 GC 对比

| 维度 | Parallel | G1 | **ZGC** | Shenandoah |
|------|----------|-----|---------|------------|
| JDK 默认 | 8 服务端 | **9+** | 需显式开启 | 需显式开启 |
| 停顿 | 随堆变差 | ~200ms 软目标 | **<1～3ms 级** | 低毫秒级 |
| 吞吐 | 最高 | 中高 | 中（分代后↑） | 中 |
| 堆大小 | 中 | 4G～几十G | **大堆优势明显** | 大堆 |
| 核心技术 | STW 整理 | Region + 写屏障 | **染色指针 + 读屏障** | Brooks Pointer |
| 碎片 | 整理 | Region 复制 | 并发整理 | 并发整理 |

详见 [[1004-G1垃圾回收与堆内存]] G1 专题。

---

## 16. 选型指南

**适合 ZGC**：

- 堆 **≥ 8G、16G+**，G1 的 Mixed/Remark 仍造成 P99 尖刺
- 延迟 SLA 严：**P99 GC 贡献 < 10ms**
- 金融交易、实时推荐、低延迟 API、大内存缓存

**不太适合 ZGC**：

- 批处理、离线计算（要吞吐 → Parallel）
- 小堆（<4G）低 QPS（G1 足够，读屏障开销不划算）
- CPU 已极度紧张，难承受并发 GC 开销

```text
要吞吐  → Parallel
要平衡  → G1
要极低延迟 + 大堆  → ZGC（JDK 21+ 分代）
```

## 17. 常用参数

ZGC 哲学：**少调参，多观测**。

```bash
-XX:+UseZGC
-Xms16g -Xmx16g
```

| 参数 | 含义 | 说明 |
|------|------|------|
| `-XX:+UseZGC` | 启用 ZGC | JDK 23+ 默认分代 |
| `-Xms` / `-Xmx` | 堆大小 | 生产常相等 |
| `-XX:SoftMaxHeapSize` | 软堆上限 | JDK 13+，允许压力下收缩 |
| `ConcGCThreads` | 并发 GC 线程 | 通常自动 |
| `ParallelGCThreads` | STW 并行线程 | 通常自动 |
| `ZCollectionInterval` | 两次 GC 最小间隔（秒） | 调频率 |
| `ZAllocationSpikeTolerance` | 分配突增容忍度 | 防 allocation stall |
| `ZFragmentationLimit` | 触发回收的碎片阈值 | 通常自动即可 |

**与 G1 不同，没有**：

```text
❌ MaxGCPauseMillis（停顿由实现保证，非软目标）
❌ IHOP / Mixed GC
❌ -Xmn / G1NewSizePercent
```

## 18. GC 日志与关键词

```bash
-Xlog:gc*:file=gc-zgc.log:time,uptime,level,tags:filecount=5,filesize=50m
```

| 日志关键词 | 含义 |
|------------|------|
| `Pause Mark Start` | 标记开始 STW |
| `Concurrent Mark` | 并发标记 |
| `Pause Mark End` | 标记结束 STW |
| `Pause Relocate Start` | 搬迁开始 STW |
| `Concurrent Relocate` | 并发移动对象 |
| `Allocation Stall` | 分配等待 GC，需关注 |

| 现象 | 可能原因 |
|------|----------|
| 频繁 Allocation Stall | 分配过快、堆过小、并发 GC 线程不足 |
| STW 突然变长 | 根集合过大、极端引用图、查 JDK 版本 |
| 堆只升不降 | 泄漏或大缓存；需 heap dump |
| 吞吐远低于 G1 | 非分代 ZGC；升级到 JDK 21+ 分代 |

## 19. 面试速记

1. ZGC 目标：**超低停顿**，停顿几乎不随堆线性增长。
2. 核心技术：**染色指针 + 读屏障 + 多重映射 + 并发 relocation**。
3. **为什么能并发移动？** 指针带颜色，读屏障修正过期引用，不必 STW 更新全堆。
4. **和 G1 最大区别？** G1 写屏障 + Region STW 复制；ZGC 读屏障 + 并发整理。
5. **分代 ZGC**（JDK 21+）：解决早期全堆扫描吞吐低；年轻代高频轻收，吞吐接近 G1。
6. **JDK 23**：`UseZGC` 默认分代模式。
7. **SATB**：并发标记防漏标，宁可多标。
8. 堆单位是 **Page**（Small/Medium/Large），不是 G1 的等大小 Region。
9. Metaspace 与堆分开配置。
10. 代价：读屏障开销、并发阶段占 CPU、吞吐通常低于 Parallel。

# Part V：工程实践

## 20. 堆内存怎么设

| 做法 | 原因 |
|------|------|
| **`-Xms = -Xmx`** | 避免堆扩缩波动 |
| **容器留余量** | `-Xmx` 约为 limit 的 **70%～75%** |
| **Metaspace 单独配** | 堆 OOM ≠ Metaspace OOM |

```bash
-Xms16g -Xmx16g
-XX:MetaspaceSize=256m
-XX:MaxMetaspaceSize=512m
```

ZGC 优势在 **大堆**（8G+）；4G 小堆未必比 G1 更好。

---

## 21. CPU 与并发开销

```text
ZGC 并发 Mark / Relocate 会占用 CPU
建议预留 10%～25% CPU 给 GC 并发线程（视分配速率）
CPU 已打满的服务，上 ZGC 可能反而抖动
```

---

## 22. 可观测性

### 22.1 健康信号

- STW pause 持续 **< 5ms**（多数 < 2ms）
- 无频繁 **Allocation Stall**
- 堆使用率周期性下降（锯齿状）

### 22.2 排查顺序

```text
1. 确认 JDK ≥ 21，分代 ZGC 生效（JDK 23+ 默认）
2. gc.log 看 Allocation Stall 频率
3. 对齐 P99 尖刺与 Pause 时间点
4. -Xmx 是否相对峰值过小
5. JFR / heap dump 查分配热点与泄漏
```

### 22.3 工具

| 工具 | 用途 |
|------|------|
| **GCeasy** | gc.log 自动分析 |
| **jcmd** | `GC.heap_info` |
| **JFR** | 分配热点、停顿分布 |
| **Micrometer** | Prometheus 监控 GC 暂停 |

---

## 23. 升级注意

```text
JDK 11/15 的 ZGC ≠ JDK 21+ 分代 ZGC，压测务必用目标 JDK
部分监控只认 G1 日志格式，需更新
DirectBuffer、堆外内存、Metaspace 不归 ZGC 堆管理
```

---

## 24. 发布检查清单

```text
□ JDK ≥ 21（推荐），确认分代 ZGC 生效
□ -Xms = -Xmx，容器留余量
□ Metaspace 上限已设
□ GC 日志已开启并轮转
□ 压测对比：吞吐、P99、P999、CPU
□ 无频繁 Allocation Stall
□ STW pause 符合 SLA
```

### 实战一句话

> **ZGC 工程实践：JDK 21+ 分代、`-Xms=-Xmx`、大堆低延迟场景、必开 GC 日志；排查盯 Allocation Stall 与 STW 尖刺，吞吐不够先确认分代生效，小堆优先 G1。**
