## 一句话概括

**SPI = 接口在 JDK/框架里，实现在第三方 jar 里，运行时自动发现并加载。** 核心 API 是 `java.util.ServiceLoader`。注册方式是 **在 jar 里放 `META-INF/services/<接口全限定名>` 文本文件**；没有中央注册表，靠 **ClassLoader 扫描 classpath** 实现。

---

## 1. SPI 是什么

| 角色 | 说明 | 举例 |
|------|------|------|
| **Service Interface** | 调用方依赖的抽象接口 | `java.sql.Driver` |
| **Service Provider** | 接口的具体实现类 | `com.mysql.cj.jdbc.Driver` |
| **Service Loader** | 发现与加载工具 | `java.util.ServiceLoader` |
| **调用方** | 只面向接口编程 | `DriverManager`、业务代码 |

设计目标：**解耦接口与实现**，新增实现只需加 jar + 写配置文件，不改调用方代码。

```text
调用方只依赖接口
    ↓
实现方在 jar 里「注册」自己
    ↓
ServiceLoader 扫描 classpath 自动加载
```

## 2. META-INF/services 注册规则（重要）

### 2.1 文件名写什么

路径固定：

```text
META-INF/services/<接口全限定名>
```

**不是**简单接口名 `Driver`，**而是** 包名 + 接口名（Fully Qualified Binary Name）。

| 接口 | 配置文件路径 |
|------|----------------|
| `java.sql.Driver` | `META-INF/services/java.sql.Driver` |
| `com.example.spi.MessageService` | `META-INF/services/com.example.spi.MessageService` |

```text
❌ META-INF/services/Driver
❌ META-INF/services/MessageService
✅ META-INF/services/java.sql.Driver
✅ META-INF/services/com.example.spi.MessageService
```

### 2.2 文件内容写什么

**实现类的全限定名**，每行一个；`#` 开头为注释。

```text
# MySQL JDBC Driver
com.mysql.cj.jdbc.Driver
```

```text
com.example.spi.impl.EmailServiceImpl
com.example.spi.impl.SmsServiceImpl
```

### 2.3 对照关系

```text
文件名  →  谁是 Service Interface（接口全限定名）
内容    →  谁是 Service Provider（实现类全限定名）
```

### 2.4 「注册」的本质

**没有运行时注册中心**，没有 API 回调。实现方在打包时把文本文件放进 jar，成为 classpath 上的一个 **资源 URL**。运行时由 `ServiceLoader` 扫描发现。

```text
mysql-connector.jar
└── META-INF/
    └── services/
        └── java.sql.Driver   ← 普通 UTF-8 文本资源
```

## 3. JDK 原生 SPI 完整示例

### 3.1 定义接口

```java
package com.example.spi;

public interface MessageService {
    void send(String msg);
}
```

### 3.2 写实现

```java
package com.example.spi.impl;

public class EmailServiceImpl implements MessageService {
    @Override
    public void send(String msg) {
        System.out.println("[Email] " + msg);
    }
}
```

### 3.3 注册（resources 目录）

```text
META-INF/services/com.example.spi.MessageService
```

```text
com.example.spi.impl.EmailServiceImpl
```

### 3.4 加载使用

```java
ServiceLoader<MessageService> loader = ServiceLoader.load(MessageService.class);

for (MessageService service : loader) {
    service.send("hello");
}
```

## 4. META-INF/services 发现与加载的实现原理

实现类：`java.util.ServiceLoader` 内部类 **`LazyClassPathLookupIterator`**。

### 4.1 整体流程

```text
【注册阶段 - 打包时】
实现方写 META-INF/services/<接口全限定名>
    → 打进 jar，成为 classpath 资源

【发现阶段 - 运行时】
ServiceLoader.load(接口.class, TCCL)
    │
    ▼
fullName = "META-INF/services/" + 接口.getName()
    │
    ▼
TCCL.getResources(fullName)
    → 返回 classpath 上所有同名配置文件的 URL 列表
    │
    ▼
对每个 URL：UTF-8 按行 parse → 得到实现类名列表
    │
    ▼
iterator / for-each 时（懒加载）：
    Class.forName(实现类, false, loader)
    → getConstructor().newInstance()
    → 返回 Provider 实例
```

### 4.2 定位配置文件

```java
static final String PREFIX = "META-INF/services/";
String fullName = PREFIX + service.getName();
// 例：META-INF/services/java.sql.Driver

configs = loader.getResources(fullName);
// 返回 Enumeration<URL>，每个 jar 里的一份配置都是一个 URL
```

`getResources` 遍历 ClassLoader 可见的 **整个 classpath**：

```text
file:/app.jar!/BOOT-INF/lib/mysql-connector.jar!/META-INF/services/java.sql.Driver
file:/app.jar!/BOOT-INF/lib/postgresql.jar!/META-INF/services/java.sql.Driver
file:/project/target/classes/META-INF/services/com.example.spi.MessageService
```

**多个 jar 有同名文件 → 全部返回，合并加载，不会互相覆盖。**

### 4.3 解析规则（parseLine）

| 规则 | 说明 |
|------|------|
| 编码 | UTF-8 |
| `#` | 注释，后面内容丢弃 |
| trim | 去掉首尾空白，空行跳过 |
| 不允许空格/Tab | 类名中不能含空白 |
| 类名校验 | 合法 Java 标识符 + `.` 分隔 |
| 去重 | `Set<String> providerNames`，重复类名只保留一次 |
| 顺序 | `LinkedHashSet` 保持文件内顺序；多 jar 按 `getResources` 返回顺序 |

非法示例（抛 `ServiceConfigurationError`）：

```text
com.mysql Driver     # 含空格
com.mysql.;Driver    # 非法标识符
```

### 4.4 懒加载与实例化

`ServiceLoader.load()` **不会立刻实例化**；`iterator()` / `for-each` 时才加载：

```java
Class<?> clazz = Class.forName(cn, false, loader);  // 只加载，不初始化
if (service.isAssignableFrom(clazz)) {
    Constructor<? extends S> ctor = clazz.getConstructor();
    return ctor.newInstance();  // 无参构造
}
```

要求：实现类 **public**，有 **public 无参构造**。

### 4.5 多 jar 合并示例

```text
mysql-connector.jar  → com.mysql.cj.jdbc.Driver
postgresql.jar       → org.postgresql.Driver
```

`DriverManager` 通过 SPI 可发现 **两个** Driver，按 classpath 顺序排列；业务侧按 URL 前缀匹配具体驱动。

## 5. SPI 与 ClassLoader：为什么要 TCCL

> TCCL 产生时机、异步错位、用错 ClassLoader 导致哪些异常，详见 [[1003-TCCL线程上下文类加载器]]。

### 5.1 双亲委派带来的问题

```text
java.sql.Driver          ← 接口在 JDK（Bootstrap / Platform）
com.mysql.cj.jdbc.Driver ← 实现在 mysql-connector.jar（App / LaunchedURLClassLoader）
DriverManager            ← 由 Bootstrap 加载
```

标准双亲委派：**父加载器不会向下问子加载器要类**。

```text
Bootstrap 加载 DriverManager
    → 无法委派到 AppClassLoader 加载 MySQL 实现
    → 没有 TCCL 则 SPI 失败
```

### 5.2 TCCL 的解法

```java
// ServiceLoader.load 无参版本
ClassLoader cl = Thread.currentThread().getContextClassLoader();
ServiceLoader.load(Driver.class, cl);

// DriverManager 内部逻辑（简化）
ServiceLoader.load(Driver.class, TCCL);
```

```text
TCCL = AppClassLoader / LaunchedURLClassLoader / WebappClassLoader
    → 扫描 BOOT-INF/lib 或 WEB-INF/lib
    → Class.forName("com.mysql.cj.jdbc.Driver", false, TCCL)
```

**SPI 绕过双亲委派的关键：`Class.forName(..., TCCL)`，不是注册文件本身。**

### 5.3 各环境 TCCL

| 环境 | TCCL 通常是谁 |
|------|----------------|
| `main` 普通启动 | AppClassLoader |
| Spring Boot `java -jar` | LaunchedURLClassLoader |
| Tomcat 处理请求 | WebappClassLoader |
| 新建异步线程 | TCCL 可能不对，需手动传递（详见 [[1003-TCCL线程上下文类加载器]]） |

### 5.4 相关机制

| 机制 | 作用 |
|------|------|
| **TCCL** | 高层代码反向借用应用 ClassLoader |
| **子优先 loadClass**（Tomcat） | Web 应用优先加载 WEB-INF 里的 SPI 实现 |
| **ServiceLoader.load(Class, ClassLoader)** | 显式指定加载器，不依赖 TCCL |

## 6. ServiceLoader API 要点

```java
// 默认：TCCL
ServiceLoader.load(MessageService.class);

// 显式 ClassLoader（异步/框架推荐）
ServiceLoader.load(MessageService.class, myClassLoader);

// 已安装 Provider（JDK 扩展层）
ServiceLoader.loadInstalled(MessageService.class);

// JDK 9+ 模块 Layer
ServiceLoader.load(layer, MessageService.class);
```

ClassLoader 选择优先级：**显式参数 > TCCL > 系统类加载器**。

## 7. JDK 9+ 模块化补充

除 classpath SPI 外，模块可用 `provides`：

```java
// module-info.java
module com.mysql.driver {
    provides java.sql.Driver with com.mysql.cj.jdbc.Driver;
}
```

`ServiceLoader` 查找顺序：

```text
1. ModuleServicesLookupIterator（模块 provides）
2. LazyClassPathLookupIterator（META-INF/services）
```

**named module** 里的 classpath provider 会被忽略：

```java
if (clazz.getModule().isNamed()) {
    continue;  // 跳过
}
```

## 8. 常见实例

| 场景 | 接口 | 注册路径 |
|------|------|----------|
| JDBC | `java.sql.Driver` | `META-INF/services/java.sql.Driver` |
| SLF4J 2.x | `org.slf4j.spi.SLF4JServiceProvider` | 对应 services 文件 |
| Spring Boot CLI | `CompilerAutoConfiguration` | `META-INF/services/...` |
| Spring Boot 自动配置 | N/A（扩展 SPI） | `spring.factories` / `AutoConfiguration.imports` |

### JDBC 流程

```text
DriverManager.getConnection(url)
    → TCCL + ServiceLoader 加载所有 Driver
    → 按 jdbc:mysql:// 等前缀匹配
    → 建立连接
```

## 9. Spring 中的 SPI 扩展

| 版本       | 配置文件                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| Boot 2.x | `META-INF/spring.factories`                                                        |
| Boot 3.x | `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` |

```properties
# spring.factories
org.springframework.boot.autoconfigure.EnableAutoConfiguration=\
com.example.MyAutoConfiguration
```

`SpringFactoriesLoader` 用 **LaunchedURLClassLoader** 扫描所有 jar，思想与 SPI 一致：**声明式注册 + 运行时发现**。

## 10. 手写模拟 ServiceLoader（理解本质）

```java
ClassLoader cl = Thread.currentThread().getContextClassLoader();
String path = "META-INF/services/java.sql.Driver";

Enumeration<URL> urls = cl.getResources(path);
while (urls.hasMoreElements()) {
    URL url = urls.nextElement();
    try (BufferedReader br = new BufferedReader(
            new InputStreamReader(url.openStream(), StandardCharsets.UTF_8))) {
        String line;
        while ((line = br.readLine()) != null) {
            int idx = line.indexOf('#');
            if (idx >= 0) line = line.substring(0, idx);
            line = line.trim();
            if (!line.isEmpty()) {
                Class<?> impl = Class.forName(line, false, cl);
                System.out.println("found: " + impl);
            }
        }
    }
}
```

即 JDK 核心的 **扫资源 → 读类名 → loadClass**，外加校验与实例化。

## 11. 局限、坑与对策

| 问题 | 说明 | 对策 |
|------|------|------|
| 全量加载 | 默认实例化所有 Provider | 自行封装筛选逻辑 |
| 无法按名选择 | 没有 `load("mysql")` | 遍历后按条件选 |
| 多 jar 冲突 | 同名 services 文件会合并 | 业务侧去重/优先级 |
| TCCL 错位 | 异步线程用了错误 ClassLoader | 传递 TCCL 或显式 ClassLoader（见 [[1003-TCCL线程上下文类加载器]]） |
| 实现类约束 | 需 public 无参构造 | 保证可访问性 |
| 无生命周期 | 不像 Spring Bean | 框架封装管理 |

### 异步线程正确写法

```java
ClassLoader cl = Thread.currentThread().getContextClassLoader();
executor.submit(() -> {
    Thread.currentThread().setContextClassLoader(cl);
    ServiceLoader.load(MyService.class);
});
```

## 12. SPI vs 其他方式

| 方式 | 特点 |
|------|------|
| **SPI** | 零侵入、可插拔、配置文件驱动；适合 JDK/框架扩展点 |
| 工厂 + new | 简单，调用方耦合实现 |
| Spring @Autowired | 容器管理生命周期 |
| 反射 Class.forName | 硬编码类名 |
| OSGi / 插件框架 | 更强隔离，更复杂 |

## 14. 常见错误排查

| 现象 | 原因 |
|------|------|
| 找不到 Provider | 路径错、接口全名写错、不在 classpath |
| `ServiceConfigurationError` | 类名非法、类不存在、无无参构造、未实现接口 |
| 多个实现全出来 | 设计如此，需业务筛选 |
| 异步找不到 | TCCL 未传递或用错 ClassLoader |
| `ClassNotFoundException` / `No suitable driver` | TCCL 指向的 classpath 不含实现 jar |
| `ClassCastException: A cannot be cast to A` | 同名类被不同 ClassLoader 加载 |
| Boot 3 模块 jar 不生效 | named module 需用 `provides` |

## 15. 面试速记

1. **SPI 是什么**：接口与实现分离；`META-INF/services/<接口全限定名>` 注册；`ServiceLoader` 发现加载。
2. **文件名 vs 内容**：文件名 = 接口全限定名；内容 = 实现类全限定名。
3. **实现原理**：`getResources` 扫 classpath → UTF-8 解析 → `Class.forName` + 无参构造。
4. **为何需要 TCCL**：双亲委派下 Bootstrap 类无法直接加载应用 jar 实现。
5. **JDBC 经典题**：`Driver` 在 JDK，驱动在 connector jar，靠 TCCL + SPI。
6. **多 jar**：同名 services 文件合并，全部加载。
7. **Spring Boot**：`spring.factories` / `AutoConfiguration.imports` 是 SPI 思想扩展。
8. **异步**：传递 TCCL 或显式 `ClassLoader`（详见 [[1003-TCCL线程上下文类加载器]]）。
9. **错 ClassLoader**：在错误 classpath 上扫不到 `META-INF/services` 或 load 不了实现类。
