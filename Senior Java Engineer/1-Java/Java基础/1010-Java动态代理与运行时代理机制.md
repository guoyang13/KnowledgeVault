# Java 动态代理与运行时代理机制

## 摘要

动态代理是在运行时生成代理类型或代理实例，让调用方继续面向原接口或父类型编程，同时把方法调用转交给统一的拦截器。它解决了日志、事务、权限、远程调用等横切逻辑无法为每个业务类型重复手写包装类的问题。

Spring AOP、MyBatis Mapper 和部分 RPC 客户端都会使用动态代理，但动态代理本身属于 Java 运行时与字节码机制，不属于 Spring 专有能力。

## 与静态代理的区别

| 维度 | 静态代理 | 动态代理 |
| --- | --- | --- |
| 代理类产生时间 | 编译前手写 | 运行时生成 |
| 复用方式 | 每个接口或类各写一份 | 一套拦截逻辑服务多个类型 |
| 调用入口 | 代理类的显式方法 | 通用 InvocationHandler / MethodInterceptor |
| 常见用途 | 简单适配和包装 | AOP、Mapper、RPC、插件 |

共同点是调用方持有代理对象，代理决定何时以及如何调用真实目标。

## JDK 动态代理

JDK 动态代理面向接口，通过 `Proxy` 和 `InvocationHandler` 创建代理实例：

```java
UserService proxy = (UserService) Proxy.newProxyInstance(
        UserService.class.getClassLoader(),
        new Class<?>[] {UserService.class},
        (proxyObject, method, args) -> {
            System.out.println("before");
            Object result = method.invoke(target, args);
            System.out.println("after");
            return result;
        });
```

调用链：

```text
调用方
  → JDK 代理实例的方法
  → InvocationHandler#invoke()
  → 前置逻辑
  → Method#invoke(target, args)
  → 后置逻辑
```

主要边界：

- 代理暴露的是指定接口，不能凭空代理一个没有接口的具体类 API。
- 目标对象不是必须条件；MyBatis Mapper 和 RPC 客户端可以直接把接口方法转换成 SQL 或网络请求。
- `equals()`、`hashCode()`、`toString()` 等方法也会进入调用处理器，需要框架明确语义。

## CGLIB 子类代理

CGLIB 通过生成目标类的子类并重写可覆盖方法实现拦截。Spring Framework 内部包含重新打包的 CGLIB 实现。

```text
调用方
  → 运行时生成的目标类子类
  → MethodInterceptor
  → 前置逻辑
  → 目标方法或 MethodProxy
  → 后置逻辑
```

主要边界：

- `final` 类不能被继承，因此不能使用子类代理。
- `final`、private 等不能被子类覆盖的方法无法拦截。
- 构造、可见性和模块访问限制会影响代理生成。
- 代理对象是目标类型的子类，但仍不等同于原始实例。

## 两种机制对照

| 维度 | JDK 动态代理 | CGLIB 子类代理 |
| --- | --- | --- |
| 基础 | 接口实现 | 类继承 |
| 是否要求接口 | 是 | 否 |
| `final` 限制 | 不依赖目标类继承 | `final` 类/方法不能代理 |
| 通用入口 | `InvocationHandler` | `MethodInterceptor` |
| 典型场景 | Mapper、RPC 接口、面向接口的 AOP | 无接口类、需要基于具体类暴露 |

选择依据不是“哪个永远更快”，而是代理需要暴露的类型、目标类限制以及框架配置。

## 代理与装饰器

代理和装饰器都可以包装调用，但意图不同：

- 装饰器通常由业务显式组合，用于增加同一职责的能力。
- 代理通常控制访问路径，可能在运行时自动生成，并承载事务、远程调用、权限等基础设施逻辑。

## 常见应用

| 场景 | 代理做什么 |
| --- | --- |
| Spring AOP | 方法前后执行 Advisor / Interceptor 链 |
| Spring `@Transactional` | 开启、提交或回滚事务 |
| MyBatis Mapper | 把接口方法转换为映射语句执行 |
| RPC 客户端 | 把本地接口调用转换为网络请求 |
| 延迟加载 | 第一次访问时获取或创建真实对象 |

## 与 Spring 的边界

Java 代理机制只解决“如何拦截调用”。Spring AOP 还需要解决：

- 哪些 Bean 需要代理；
- 哪些 Advisor 匹配某个方法；
- 代理在 Bean 生命周期的哪个阶段创建；
- 使用 JDK 还是 CGLIB；
- 循环依赖时如何提前暴露并避免重复代理。

这些内容见 [[8-Spring-AOP代理创建详解]]。

FactoryBean 产生代理与 BeanPostProcessor 包装代理是两条不同接入路径，见 [[4-工厂Bean-FactoryBean接口体系详解]]。

## 记忆模型

```text
动态代理 = 运行时生成调用入口
拦截器   = 定义调用前后做什么
目标对象 = 可选的真实执行者
框架     = 决定代理谁、何时代理、怎样组织拦截链
```
