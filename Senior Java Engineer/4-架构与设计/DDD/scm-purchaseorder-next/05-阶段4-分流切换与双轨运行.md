# 阶段 4：分流切换与双轨运行

## 1. 阶段目标

让新服务逐步承接生产真实流量。切换必须按接口、调用方、国家、采购类型、供应商或业务单据维度灰度，任何异常都能回滚到旧服务。

## 2. 切流原则

- 先读后写。
- 先低副作用后高副作用。
- 先单一 PO 类型后全类型。
- 先内部调用方后外部/供应商端。
- 先人工触发接口后 MQ/定时任务。
- 一个灰度批次只改变一个变量。

## 3. 流量路由

推荐路由维度：

| 维度 | 用途 |
|---|---|
| 接口路径 | 先切查询，再切命令 |
| 调用方 | 先 UMP/内部系统，再供应商端 |
| 国家/地区 | 先单一国家 |
| PO 类型 | 先本地仓/低复杂类型，再跨境复杂类型 |
| 供应商白名单 | 先小批量供应商 |
| 单据白名单 | 对关键链路做指定单据验证 |

路由方式：

```text
方式 A：网关/服务治理按规则转发到新服务
方式 B：调用方新增 next Feign 客户端逐步迁移
方式 C：新服务注册兼容服务名并通过元数据灰度
```

推荐优先使用方式 A 或 B，避免新旧服务在同一服务名下随机抢流量。

## 4. 写入归属切换

双轨期间必须明确单据归属：

```text
old-owned: 旧服务创建和写入，新服务只读/影子
new-owned: 新服务创建和写入，旧服务只可查询兼容或不再处理
```

新增归属表：

```text
purchase_order_ownership
  biz_type
  biz_code
  owner_system
  cutover_batch
  created_at
```

规则：

- 新服务创建的 PO，后续所有命令必须回到新服务。
- 旧服务创建的 PO，在迁移归属前仍由旧服务处理命令。
- 禁止同一 PO 同时由新旧服务处理写命令。

## 5. 分批切换建议

### 批次 1：查询接口

接管：

- PO 详情。
- PO 分页。
- 供应商端查询。
- 仓储端查询。

回滚：

- 路由切回旧服务。
- 新服务不产生业务状态，无数据回滚。

### 批次 2：草稿保存和预校验

接管：

- 商品/物料 PO 草稿保存。
- 创建预校验。

限制：

- 只允许白名单调用方。
- 只允许新建单据，不接管旧单据修改。

### 批次 3：PO 提交和审批

接管：

- submit。
- approval callback。
- reject。
- cancel。

前置：

- 新服务 outbox 事件可靠发布完成。
- 审批回调幂等完成。

### 批次 4：发货、收货、入库

接管：

- supplier confirm delivery。
- cabinet callback。
- WMS inbound callback。
- store receipt callback。

前置：

- 外部副作用幂等键完成。
- WMS/库存/门店推送补偿入口完成。
- 新旧状态对账通过。

### 批次 5：货柜、商检、结算、异常

接管：

- 待出口订单。
- 货柜管理。
- 商检资质。
- 费用结算。
- 异常预警。

## 6. 双轨数据同步

切流后数据同步方向变为：

```text
旧服务 owner 单据：旧库 → 新库
新服务 owner 单据：新库 → 兼容读模型 / 必要时同步旧库只读兼容表
```

如果外部系统仍依赖旧库或旧服务查询，需要提供兼容读模型，但不能让旧服务继续写 new-owned 单据。

## 7. 回滚设计

按批次回滚：

- 查询：立即切路由。
- 草稿：删除或冻结新草稿，调用方重建。
- 提交/审批：只允许在未产生外部副作用前回滚。
- 发货/入库：不能简单回滚，必须走业务补偿。
- 结算：需要财务确认后补偿。

回滚要求：

- 每批切流前记录订单归属和变更窗口。
- 每个写接口有幂等键。
- 每个外部事件有 outbox 状态。
- 每个 MQ 消费有处理记录。

## 8. 退出条件

- 新服务稳定承接第一批写流量。
- new-owned 单据全生命周期闭环通过。
- 生产 P0/P1 问题为 0。
- 回滚演练完成。
- 监控、告警、补偿文档齐全。
