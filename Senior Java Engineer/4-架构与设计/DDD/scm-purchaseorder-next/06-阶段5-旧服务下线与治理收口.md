# 阶段 5：旧服务下线与治理收口

## 1. 阶段目标

当新服务已承接全部核心流量后，逐步冻结旧 `scm-procurement-service`，停止写入、停止 MQ 消费、停止定时任务，最终完成下线或只保留历史只读能力。

## 2. 下线前检查

必须确认：

- 旧服务没有 owner 单据继续写入。
- 所有入口流量已路由到新服务。
- 旧 MQ consumer group 已停止或迁移。
- 旧定时任务已停止或迁移。
- 外部系统回调地址已切到新服务。
- 历史补偿入口已在新服务重建。
- 旧库和新库全量对账完成。

## 3. 下线顺序

```text
停止新增写入口
→ 停止高风险补偿入口
→ 停止 MQ 消费者
→ 停止定时任务
→ 冻结旧库写权限
→ 保留只读查询窗口
→ 归档旧服务和旧库
```

## 4. 旧能力归档

旧服务中需要归档的内容：

- 历史数据修复脚本。
- 生产补偿接口。
- MQ 重试方式。
- 状态修复 SQL。
- Excel/PDF 特殊模板。
- 历史脏数据兼容逻辑。

归档后迁移到新服务：

```text
operations
  compensation
  datafix
  replay
  audit
```

这些能力必须有权限控制、审计日志和生产确认机制。

## 5. 旧库处理

旧库分三步：

1. 只读冻结：不允许业务写。
2. 归档备份：按月/按年归档历史表。
3. 下线或降级：保留审计查询，不再作为业务事实来源。

对于财务、审计、历史报表依赖的表，不直接删除，先迁到归档库。

## 6. 监控收口

新服务必须具备：

- 接口成功率、耗时、错误码监控。
- PO/PR 状态流转监控。
- outbox 堆积监控。
- MQ 消费失败监控。
- 外部系统调用失败监控。
- 新旧对账监控。
- 订单归属异常监控。

关键告警：

```text
new-owned 单据被旧服务写入
同一单据重复外部推送
PO/PSO 状态不一致
金额对账不一致
outbox 超时未发布
WMS/库存/结算回调失败
```

## 7. 组织与流程收口

上线后需要同步：

- 接口文档。
- 领域词汇表。
- 状态机文档。
- 生产补偿 SOP。
- DMS 查询模板。
- 告警处理手册。
- 新服务值班手册。

## 8. 退出条件

- 旧服务连续一个完整业务周期无写入。
- 旧服务 MQ 和定时任务全部停止。
- 新服务补偿能力覆盖旧服务。
- 新旧数据最终对账通过。
- 业务、测试、运维、财务确认旧服务可归档。
