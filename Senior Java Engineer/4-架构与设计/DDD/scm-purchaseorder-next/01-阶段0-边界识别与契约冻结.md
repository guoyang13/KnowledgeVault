# 阶段 0：边界识别与契约冻结

## 1. 阶段目标

在不改旧服务的前提下，完整识别旧 `scm-procurement-service` 的业务边界、接口契约、状态机、数据表、MQ、副作用和补偿入口，为新服务替换建立“不可破坏清单”。

本阶段不写新业务逻辑，只产出模型、契约和验证基线。

## 2. 范围

必须梳理：

- Feign/HTTP 接口清单。
- MQ 消费者和生产者清单。
- 定时任务清单。
- 旧库核心表和字段口径。
- PR/PO/PSO/货柜/商检/结算状态机。
- 外部系统依赖和回调链路。
- 生产补偿入口和数据修复脚本。

不纳入：

- 重构旧服务代码。
- 修改旧数据库结构。
- 切换任何生产流量。

## 3. 关键输出

### 3.1 接口契约目录

以旧服务 Feign 为基准，按业务上下文归类：

| 上下文 | 旧接口示例 | 新服务策略 |
|---|---|---|
| 采购订单 | `/feign/purchaseOrder/*` | 兼容旧协议，内部转 Command/Query |
| 采购需求 | `/feign/scm/procurement/purchaseRequisition/*` | 兼容旧协议，逐步提供 v2 协议 |
| 出口货柜 | `/feign/purchaseOrder/export/*` | 第二批接管 |
| 采购子单 | `/feign/purchaseSubOrder/*` | 不鼓励外部直接改 PSO，转为 PO 聚合命令 |
| 资质商检 | `/feign/poCommodityInspection/*`、`/feign/poQualsInfo/*` | 独立 inspection 上下文 |

### 3.2 状态机基线

需要固化至少这些状态转换：

```text
PO:
草稿
→ 待审核
→ 待定柜 / 供应商待发货
→ 供应商已发货
→ 中转仓收货/入库
→ 目的仓/门店收货/入库
→ 完成

PR:
待供应商确认
→ 待转 PO
→ 需求完结
→ 作废
```

每条状态边都要记录：

- 触发接口或 MQ。
- 前置状态。
- 目标状态。
- 同步修改哪些表。
- 事务内副作用。
- 事务提交后副作用。
- 失败补偿方式。

### 3.4 外部上下文映射

| 外部上下文 | 关系 | 防腐层端口 |
|---|---|---|
| 商品 | 上游供应方 | `GoodsCatalogPort` |
| 供应商 | 上游供应方 | `SupplierProfilePort` |

| 门店/POS | 下游门店上下文 | `StoreOrderPort` |
| 结算/畅收付 | 下游结算上下文 | `SettlementPort` |

## 4. 验证方式

建立阶段 0 基线报表：

- 近 90 天各接口调用量。
- 近 90 天各 PO 类型单量。
- 各状态每日流转量。
- MQ 消费成功/失败量。
- 生产补偿操作清单。
- 核心表行数和增量。

## 5. 退出条件

满足以下条件后进入阶段 1：

- 已形成旧接口契约清单。
- 已形成核心状态机和副作用清单。
- 已确认第一批替换范围：建议为 PO 查询 + PO 创建草稿/预校验。
- 已确认新服务名称、数据库、部署命名和灰度入口。
