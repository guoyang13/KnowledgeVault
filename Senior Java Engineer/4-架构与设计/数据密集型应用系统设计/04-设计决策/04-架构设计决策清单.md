# 架构设计决策清单

> **用途**：写设计文档、评审 PR、选型会议时逐项勾选。可作为团队 ADR 附录。

## 1. 目标与边界

- [ ] 是否明确 **数据密集型** 挑战（量 / 复杂度 / 变化速度）？
- [ ] SLA：可用性（几个 9）、p99 延迟、RPO/RTO？
- [ ] 真相源（System of Record）是哪个系统？
- [ ] 本模块是否 **限界上下文** 内可独立演化？（对照 DDD）

## 2. 数据模型与存储

- [ ] 实体关系以 1:N、N:M 还是图遍历为主？
- [ ] OLTP 与 OLAP 是否分离？
- [ ] 索引是否覆盖 95% 读路径？是否有全表扫描风险？
- [ ] Schema 变更策略（Flyway / 双写 / 兼容字段）？

## 3. 复制与读路径

- [ ] 是否读写分离？从库 lag 容忍度？
- [ ] 是否需要 **读己之所写 / 单调读**？如何实现？
- [ ] 缓存与 DB 一致性策略（TTL / 主动失效 / CDC）？

## 4. 分区与扩展

- [ ] 预期 10x 增长时的瓶颈组件？
- [ ] 分区键是否高基数、防热点？
- [ ] 跨分区操作是否禁止或有 Saga？

## 5. 事务与一致性

- [ ] 业务不变量是否文档化？
- [ ] 单库本地事务能否覆盖？若不能，用 Saga / Outbox / TCC？
- [ ] 隔离级别是否与写偏斜风险匹配？
- [ ] 全链路 **幂等键** 是否定义？

## 6. 分布式与故障

- [ ] 超时、重试、退避、熔断参数？
- [ ] 是否依赖跨节点时钟排序？（应避免）
- [ ] 分布式锁是否有 fencing / lease 意识？
- [ ] 混沌演练 / 故障注入计划？

## 7. 异步与集成

- [ ] 是否避免应用双写多存储？
- [ ] MQ 语义：at-least-once + 幂等？
- [ ] 死信、重放、Schema 演化？
- [ ] 数据血缘：谁消费谁生产？

## 8. 可运维性

- [ ] 监控：QPS、lag、p99、错误率、复制延迟？
- [ ] 告警：对账差异、消费堆积、磁盘？
- [ ] 备份恢复是否演练？
- [ ] 配置与密钥管理？

## 9. 安全与合规

- [ ] 敏感字段加密、脱敏、 retention？
- [ ] 审计日志？
- [ ] 权限最小化？
