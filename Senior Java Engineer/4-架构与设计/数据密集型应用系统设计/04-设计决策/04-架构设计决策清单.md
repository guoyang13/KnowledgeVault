# 架构设计决策清单

> **用途**：写设计文档、评审 PR、选型会议时逐项勾选。可作为团队 ADR 附录。

## 设计推理顺序

```text
先定义业务不变量
  -> 再描述负载参数
  -> 再画数据所有权
  -> 再识别事务边界
  -> 再标注读保证
  -> 再选择复制、分区、消息、缓存和流处理机制
```

产品选型应该排在推理后面。先选产品再倒推语义，往往会把问题藏到运维、补偿和对账里。

## 1. 目标与边界

- [ ] 是否明确 **数据密集型** 挑战（量 / 复杂度 / 变化速度）？
- [ ] SLA：可用性（几个 9）、p99 延迟、RPO/RTO？
- [ ] 真相源（System of Record）是哪个系统？
- [ ] 本模块是否 **限界上下文** 内可独立演化？（对照 DDD）

## 2. 数据模型与存储

- [ ] 实体关系以 1:N、N:M 还是图遍历为主？
- [ ] OLTP 与 OLAP 是否分离？
- [ ] 索引是否覆盖 95% 读路径？是否有全表扫描风险？
- [ ] Schema 变更策略（Flyway / 双写 / 兼容字段）？

## 3. 复制与读路径

- [ ] 是否读写分离？从库 lag 容忍度？
- [ ] 是否需要 **读己之所写 / 单调读**？如何实现？
- [ ] 缓存与 DB 一致性策略（TTL / 主动失效 / CDC）？

## 4. 分区与扩展

- [ ] 预期 10x 增长时的瓶颈组件？
- [ ] 分区键是否高基数、防热点？
- [ ] 跨分区操作是否禁止或有 Saga？

## 5. 事务与一致性

- [ ] 业务不变量是否文档化？
- [ ] 单库本地事务能否覆盖？若不能，用 Saga / Outbox / TCC？
- [ ] 隔离级别是否与写偏斜风险匹配？
- [ ] 全链路 **幂等键** 是否定义？

## 6. 分布式与故障

- [ ] 超时、重试、退避、熔断参数？
- [ ] 是否依赖跨节点时钟排序？（应避免）
- [ ] 分布式锁是否有 fencing / lease 意识？
- [ ] 混沌演练 / 故障注入计划？

## 7. 异步与集成

- [ ] 是否避免应用双写多存储？
- [ ] MQ 语义：at-least-once + 幂等？
- [ ] 死信、重放、Schema 演化？
- [ ] 数据血缘：谁消费谁生产？
- [ ] 衍生视图（缓存/搜索/数仓）是否能从真相源重建？

## 8. 可运维性

- [ ] 监控：QPS、lag、p99、错误率、复制延迟？
- [ ] 告警：对账差异、消费堆积、磁盘？
- [ ] 备份恢复是否演练？
- [ ] 配置与密钥管理？

## 9. 安全与合规

- [ ] 敏感字段加密、脱敏、 retention？
- [ ] 审计日志？
- [ ] 权限最小化？

## 设计推理模板

### 业务不变量

| 不变量 | 涉及数据 | 违反后果 | 保护机制 |
|---|---|---|---|
| 示例：订单不能超卖 | 库存、订单、支付状态 | 资损、履约失败 | 单行原子更新 / 预留库存 / TCC |
|  |  |  |  |

### 数据所有权

| 数据 | 真相源 | 衍生视图 | 同步方式 | 可重建吗 |
|---|---|---|---|---|
| 订单 | order_db.orders | ES、数仓、缓存 | Outbox/CDC | 是 |
|  |  |  |  |  |

### 读保证

| API | 数据来源 | 需要的读保证 | 实现方式 |
|---|---|---|---|
| 用户提交后查看订单 | 主库/缓存 | 读己之所写 | 写后短时间读主库或按版本读 |
| 订单列表翻页 | 从库/搜索 | 单调读 | 用户固定副本或带版本水位 |
| 搜索结果 | ES | 最终一致 | 展示同步中状态、监控 lag |

### 失败处理

| 场景 | 系统看到什么 | 用户看到什么 | 处理方式 |
|---|---|---|---|
| MQ 投递失败 | outbox 未发送 | 订单已创建，通知延迟 | 重试、告警、补偿 |
| 消费者重复消费 | 幂等键冲突 | 无感 | 唯一键/版本去重 |
| 从库延迟 | 读到旧数据 | 可能看不到刚提交 | 读主或提示同步中 |
| 分布式锁过期 | 旧持有者仍写入 | 数据错乱风险 | fencing token / 版本校验 |

## 评审时的十个高价值问题

- 这份数据的 System of Record 是哪里？
- 写路径是否同时写了多个系统？如果是，失败后如何恢复？
- 读路径是否读副本、缓存或搜索索引？需要什么读保证？
- 哪些业务不变量必须被数据库或事务机制保护？
- 当前隔离级别能防住写偏斜吗？
- 分区键是否会形成热点？范围查询怎么办？
- 消息重复、乱序、延迟、丢失时业务怎么处理？
- Schema 变化时旧消费者会不会崩？
- 哪些数据可以删除后重建？重建流程是否演练过？
- 哪个设计选择最难回滚？
