# DDIA 术语卡片

> 速查用。详细解释见对应章节精读。

## 可靠性 / 可伸缩性

| 术语 | 一句话 |
|---|---|
| **Fault** | 系统某部分偏离标准，可容忍 |
| **Failure** | 用户可见的服务失败 |
| **容错** | 通过冗余、快速恢复降低 failure |
| **负载参数** | 描述负载的指标，如 QPS、读写比、活跃用户 |
| **吞吐量** | 单位时间处理记录数 |
| **百分位延迟** | p50/p95/p99，比平均值更能反映用户体验 |
| **尾部延迟** | 高百分位延迟，常由 GC、排队、慢节点引起 |

## 数据模型 / 存储

| 术语 | 一句话 |
|---|---|
| **Schema-on-read** | 读时解析结构（文档库） |
| **Schema-on-write** | 写时校验结构（关系库） |
| **OLTP** | 在线事务，行存，低延迟读写 |
| **OLAP** | 在线分析，列存，扫描聚合 |
| **LSM-Tree** | 写优化：先写内存/WAL，再合并 SSTable |
| **B-Tree** | 读优化：原地更新页（InnoDB） |
| **SSTable** | 不可变有序键值文件，支持范围查询 |
| **列存储** | 按列压缩存储，适合分析查询 |

## 编码 / 演化

| 术语 | 一句话 |
|---|---|
| **向后兼容** | 新代码读旧数据 |
| **向前兼容** | 旧代码读新数据 |
| **Avro / Protobuf** | 带 Schema ID 的二进制编码，演化友好 |
| **Schema Registry** | 集中管理消息 Schema 版本 |

## 复制 / 分区

| 术语 | 一句话 |
|---|---|
| **Leader / Follower** | 主写从读，异步或半同步复制 |
| **Replication lag** | 从库落后主库的时间 |
| **Multi-leader** | 多主写入，需冲突解决 |
| **Leaderless** | 无主，Quorum 读写（Dynamo 风格） |
| **W + R > N** | 读写 Quorum 重叠，保证读到最新 |
| **Hinted handoff** | 临时节点故障时写提示，恢复后补 |
| **Anti-entropy** | 后台比对副本修复不一致 |
| **Partition / Shard** | 按 Key 把数据分到不同节点 |
| **Hot spot** | 某分区负载过高 |
| **Rebalancing** | 节点变化时迁移分区 |

## 事务 / 一致性

| 术语 | 一句话 |
|---|---|
| **ACID** | 原子、一致、隔离、持久 |
| **脏读 / 不可重复读 / 幻读** | 三种经典并发异常 |
| **写偏斜 Write skew** | 两个事务基于相同前提各写一行，破坏不变量 |
| **2PL** | 两阶段锁，可串行化但易死锁 |
| **SSI** | 可串行化快照隔离，乐观检测冲突 |
| **2PC** | 两阶段提交，协调者与参与者 |
| **线性一致性** | 所有操作看起来在单副本上按实时顺序发生 |
| **因果一致性** | 有因果关系的操作顺序对所有可见 |
| **共识 Consensus** | 多节点对单一值达成一致（Raft） |
| **Fencing token** | 防止过期 leader 写存储 |

## 分布式故障

| 术语 | 一句话 |
|---|---|
| **部分失效** | 分布式特有：部分节点/网络坏 |
| **超时** | 无法区分慢与死，只能猜测 |
| **Unbounded delay** | 网络延迟无上界，不能假设上限 |
| **Clock skew** | 节点时钟不同步 |
| **Process pause** | GC/STW 导致「假死」 |
| **Byzantine fault** | 节点任意作恶（区块链场景） |

## 批处理 / 流处理

| 术语 | 一句话 |
|---|---|
| **MapReduce** | Map 分片计算 + Shuffle + Reduce 聚合 |
| **Dataflow engine** | Spark/Flink，内存迭代，比 MR 快 |
| **物化视图** | 预计算并存储查询结果 |
| **CDC** | Change Data Capture，数据库变更流 |
| **Event sourcing** | 以事件序列为真相源 |
| **Tumbling / Sliding window** | 滚动 / 滑动时间窗口 |
| **Exactly-once** | 语义目标，通常通过幂等 + 去重实现 |
| **Lambda 架构** | 批层 + 速度层 + 服务层 |
| **Kappa 架构** | 全用流处理，历史用重放 |
