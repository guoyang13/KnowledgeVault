# 复制、分区与扩展性

> Part II 前半（第 5–6 章）。做**读写分离、分库分表、多活**前读此篇。

## 扩展路径

```text
1. 垂直扩展（更强机器）
2. 读扩展：复制 + 缓存 + CDN
3. 写扩展：分区（Sharding）
4. 功能扩展：拆服务 + 专用存储
```

## 复制策略选择

| 需求 | 策略 |
|---|---|
| 读多写少、可容忍 lag | 主从异步 + 缓存 |
| 同机房 RPO≈0 | 半同步 / 同步复制 |
| 多数据中心写 | 多主（冲突解决）或 单元化 |
| 高可用写 AP | Leaderless Quorum |

## 读保证与产品映射

| 产品行为 | 技术保证 |
|---|---|
| 发帖立即可见 | 读己之所写 / 读主 |
| 时间线不倒退 | 单调读 |
| 评论顺序正确 | 一致前缀 / 单分区有序 |
| 全局点赞数 | 最终一致 + 异步聚合 |

## 分区键设计原则

1. **高基数**：避免所有数据落一分区。
2. **与访问一致**：常一起查的 Key 同分区。
3. **可再平衡**：预留虚拟分区 / 一致性哈希。
4. **避免热点**：促销 SKU 加随机后缀或独立计数服务。

## 复制 + 分区组合故障

| 故障 | 现象 | 缓解 |
|---|---|---|
| 从库 lag | 旧读 | 关键读走主、版本号校验 |
| 分区不均 | 热点节点 | 监控分区 QPS、动态分裂 |
| 再平衡 | 迁移中延迟 | 渐进迁移、双读 |
| 脑裂 | 双主写 | Raft、fencing、STONITH |

## 设计评审必问

- RPO/RTO 数字是多少？是否演练过 failover？
- 分区后跨分片查询是否被禁止或走 ES/数仓？
- 缓存失效策略与 DB 复制 lag 是否一起考虑？
