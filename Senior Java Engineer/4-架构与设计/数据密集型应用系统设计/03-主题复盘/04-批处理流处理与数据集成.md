# 批处理、流处理与数据集成

> Part III 复盘（第 10–12 章）。做**报表、实时大屏、搜索同步、数仓**前读此篇。

## Lambda vs Kappa

| 架构 | 组成 | 优点 | 缺点 |
|---|---|---|---|
| **Lambda** | 批层 + 速度层 + 服务层 | 准确+实时 | 两套逻辑 |
| **Kappa** | 全流 + 重放历史 | 逻辑统一 | 重放成本、状态大 |

实践：**流为主 + 批校正** 或 **CDC 统一入湖**。

## 数据集成模式

```text
System of Record (MySQL)
    │
    ├─ CDC (binlog) ──► Kafka ──► ES / Redis / 数仓
    │
    ├─ 应用 Outbox ──► MQ ──► 下游服务
    │
    └─ 批 ETL (T+1) ──► 报表 / 特征
```

### 双写问题

```text
❌ 应用写 DB + 写 ES（任一失败不一致）
✅ 只写 DB → CDC 更新 ES
✅ 同事务写 Outbox → 异步投递
```

## 流处理检查项

| 项 | 说明 |
|---|---|
| 分区键 | 保证业务有序的最小范围 |
| 幂等 | `INSERT ON DUPLICATE` / Redis set |
| 死信 |  poison message 隔离 |
| 回溯 | 保留天数、重放流程 |
| Schema | Registry + 兼容策略 |
