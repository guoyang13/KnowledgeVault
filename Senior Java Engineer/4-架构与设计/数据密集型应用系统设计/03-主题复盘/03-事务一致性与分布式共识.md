# 事务、一致性与分布式共识

> Part II 后半（第 7–9 章）。做**分布式事务、库存扣减、支付**前读此篇。

## 隔离级别选型（单库）

| 业务 | 建议 | 原因 |
|---|---|---|
| 普通 CRUD | RC 或 RR | 平衡性能 |
| 金融账务 | RR + 显式锁 / Serializable | 防写偏斜 |
| 只读报表 | RC + 快照从库 | 避免长事务 |
| 计数器 | 单行 UPDATE / Redis Lua | 缩小冲突面 |

## 分布式一致性方案对比

| 方案 | 一致性 | 可用性 | 复杂度 | 适用 |
|---|---|---|---|---|
| 本地事务 | 强 | 高 | 低 | 单服务单库 |
| 2PC / XA | 强 | 低（阻塞） | 高 | 遗留集成，慎用 |
| Seata AT | 较强 | 中 | 中 | 同构 Java 微服务 |
| TCC | 可调 | 中 | 高 | 资金、库存预留 |
| Saga | 最终 | 高 | 中 | 长流程订单 |
| 本地消息表 / Outbox | 最终 | 高 | 中 | **推荐默认** |
| 事务消息（MQ） | 最终 | 高 | 中 | 与 Outbox 类似 |

## 决策树

```text
能否用一个聚合 + 一个本地事务完成？
  ├─ 是 → 本地 ACID（首选）
  └─ 否 → 是否跨服务且需即时一致？
        ├─ 是 → TCC / 可串行化资源（慎用 2PC）
        └─ 否 → Saga / Outbox + 幂等 + 对账
```

## 共识与协调服务

| 组件 | 用途 |
|---|---|
| etcd / ZooKeeper | 选主、配置、分布式锁（带 fencing） |
| Raft 日志 | 复制状态机 |
| 版本号 / 乐观锁 | 低冲突并发控制 |

## 常见反模式

- `@Transactional` 内调 HTTP，超时导致 DB 长事务。
- 分布式锁无 fencing，STW 后双写。
- 「最终一致」无对账、无补偿、无超时告警。

## 设计评审必问

1. 业务不变量是什么？在哪个边界保证？
2. 失败时用户看到什么？能否自动补偿？
3. 幂等键是否全链路传递？
4. 对账任务与监控是否就绪？
