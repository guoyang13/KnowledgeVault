# 第 07 章：事务

> 本章目标：精确理解 **ACID、隔离级别、异常现象**，为选型与排查「脏数据」提供语言。

## 初学者先抓住一句话

**事务** 把多步操作绑成逻辑单元；**隔离级别** 决定并发下你能接受哪种异常。

## ACID（审慎理解）

| 字母 | 含义 | 注意 |
|---|---|---|
| A 原子 | 全成功或全失败 | 分布式原子更难 |
| C 一致 | 应用不变量成立 | DB 不保证所有业务规则 |
| I 隔离 | 并发像串行 | 各级别不同 |
| D 持久 | 提交后不丢 | 依赖复制与 fsync |

## 弱隔离级别

### 读已提交 Read Committed

- 只见已提交；写时覆盖已提交值。
- 防止脏读；**不防**不可重复读、幻读。

### 快照隔离 Snapshot Isolation（MVCC）

- 每事务读 **一致快照**。
- 防止脏读、不可重复读；**写偏斜** 仍可能发生。
- PostgreSQL、Oracle 的「可重复读」常实现为 SI。

### 可重复读 Repeatable Read（MySQL InnoDB）

- 快照读 + 间隙锁防幻读（部分场景）。
- 仍可能有 **写偏斜**（经典：会议室预订、库存扣减两行）。

### 写偏斜 Write Skew 示例

```text
规则：至少一名值班医生在岗
事务 A：查 2 人在岗 → 请假 Alice
事务 B：查 2 人在岗 → 请假 Bob
结果：0 人在岗 —— 各自行合法，全局非法
```

**解法**：可串行化、显式锁范围、物化冲突行（计数器）。

## 可串行化 Serializable

| 实现 | 特点 |
|---|---|
| 实际串行执行 | 单线程，简单但慢 |
| 两阶段锁 2PL | 读写锁，易死锁 |
| **SSI** | 乐观，检测读写冲突，PostgreSQL 提供 |

## 架构设计检查清单

- [ ] 是否默认 RR 但未测写偏斜场景？
- [ ] 长事务是否占满 MVCC 版本链导致慢查询？
- [ ] `@Transactional` 是否跨 RPC 导致分布式假事务？
- [ ] 只读报表是否应 `READ ONLY` 或走从库快照？

## 与 Java 后端

- **Spring `@Transactional`**：默认传播、隔离级别与 DB 对齐；`rollbackFor` 显式声明。
- **MySQL InnoDB**：默认 RR + MVCC；`SELECT ... FOR UPDATE` 当前读。
- **乐观锁**：`version` 字段代替悲观锁，适合冲突少。
- **分布式事务**：Seata AT/TCC/Saga —— 见 [[03-事务一致性与分布式共识]]，优先本地事务 + Outbox。

## 本章小结

- 隔离级别不是越高越好：性能与异常 trade-off。
- **写偏斜** 是 RR/SI 下最容易被忽视的 bug。
- 业务不变量应写进设计文档，并映射到锁或串行化策略。
