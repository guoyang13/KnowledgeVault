# 推理模型（Reasoning Model）

> 把"思考过程（thinking / chain-of-thought）"作为一类显式训练目标的模型，用更多推理 token 换更高准确率。

> 2026-07 更新：推理模型已经从“少数 reasoning 专用模型”变成主流模型标配。常见接口会提供 `reasoning_effort`、thinking budget、think / non-think 或 extended/adaptive thinking，用来在成本、延迟和质量之间做选择。

## 关键点
- **核心思想**：不只是 prompt 时让模型 CoT，而是**训练阶段就奖励高质量的思考链**。
- **训练秘诀**：大量 [[AI/00-AI学习体系/02-概念库/02-训练与推理/02-RLVR|RLVR]]（可验证奖励 RL）+ 数学/代码/逻辑题，配合 [[AI/00-AI学习体系/02-概念库/02-训练与推理/03-PRM与ORM|PRM与ORM]]。
- **Thinking Token / Reasoning Token**：模型在输出最终答案前会先生成大段思考，思考内容可见或隐藏。
- **Hybrid Reasoning**：同一模型可在"快答 / 深思"间切换，通过 `reasoning_effort`、`thinking_budget` 控制。
- **Agentic Reasoning**：推理不只用于答案生成，也用于任务规划、工具选择、代码修改、浏览器操作和失败恢复。

## 代表模型
- **OpenAI GPT-5.x**：API 层提供 reasoning effort，强模型面向复杂推理、代码和工具任务。
- **Anthropic Claude Fable 5 / Opus 4.8 / Sonnet 5**：强调 extended/adaptive thinking、长任务和 agentic coding。
- **Google Gemini 2.5 / 3 系**：thinking、工具、搜索、代码执行、computer use 与多模态能力结合。
- **DeepSeek-R1 / V3.1 / V4**：低成本 reasoning、think/non-think 混合、工具调用和长上下文。
- **Qwen3**：thinking / non-thinking 混合模式，多语言、代码和 Agent/MCP 支持。
- **Mistral Magistral**：Mistral 的 reasoning 模型路线，强调透明、多语言和企业场景。

## 应用边界
- **适合**：数学、代码、复杂规划、Agent 长任务。
- **不适合**：简单对话、低延迟场景（思考 token 很贵且慢）。
- **工程建议**：不要所有请求都开最高 thinking；优先用 [[AI/00-AI学习体系/02-概念库/01-模型层/08-Model Routing|Model Routing]] 分流，再对失败样本升级推理强度。
