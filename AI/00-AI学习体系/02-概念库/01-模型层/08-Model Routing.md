# Model Routing

> 在多个模型之间动态分流请求，用更低成本和延迟覆盖多数任务，把困难任务交给更强模型。

> 2026-07 更新：路由不只发生在“多个外部模型之间”，也发生在同一模型内部的快答/深思、thinking budget、reasoning effort、工具调用和长上下文策略之间。

## 关键点
- **路由目标**：在质量、成本、延迟、上下文长度、工具能力之间做权衡。
- **常见策略**：规则路由、分类器路由、LLM 自评路由、级联式 fallback。
- **快慢模型组合**：小模型先处理简单意图、摘要、格式转换；大模型负责复杂推理、代码和长任务。
- **质量控制**：低置信度、工具失败或用户追问时升级到强模型。
- **推理强度路由**：简单请求不开 thinking，复杂请求提高 reasoning effort。
- **工具路由**：事实查询走搜索/RAG，计算走代码执行，系统操作走受限工具。
- **上下文路由**：短请求直接回答，长资料走检索、压缩或长上下文模型。

## 典型路由模式

```text
用户请求
→ 意图/风险/复杂度分类
→ 小模型/快答尝试
→ 需要事实则 RAG/搜索
→ 需要操作则工具/Agent
→ 失败或低置信度则升级强模型/高 reasoning effort
→ 记录样本进入 eval
```

## 2026 工程启发

- 有了强模型，也不意味着所有请求都用最强模型。
- 有了 1M 上下文，也不意味着所有资料都直接塞进去。
- 有了 Agent，也不意味着所有任务都让模型自由规划。
- 好的路由系统本质是“成本、延迟、质量、安全”的调度器。
