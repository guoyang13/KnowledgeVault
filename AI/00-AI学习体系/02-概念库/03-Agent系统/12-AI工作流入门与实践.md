# AI 工作流入门与实践

> 更新时间：2026-07-10。
> **AI 工作流**是把大模型嵌进「有顺序、可重复、可分支」的业务步骤里，而不是每次从零聊天。
>
> 深入：[[AI/00-AI学习体系/02-概念库/03-Agent系统/11-AI工作流-Graph与Loop|AI工作流-Graph与Loop]] · [[AI/00-AI学习体系/02-概念库/03-Agent系统/01-Workflow vs Agent|Workflow vs Agent]]

## 一句话

```text
AI 工作流 = 业务流程 + AI 节点 + 判断/工具/人工卡点
```

像流水线：每一步做什么、失败怎么办、要不要人审，都事先定好。

---

## 和传统自动化的区别

| | 传统工作流（RPA/脚本） | AI 工作流 |
|---|---|---|
| 规则 | 固定、确定性 | 部分步骤靠模型理解自然语言 |
| 输入 | 结构化数据 | 文本、文档、对话、图片等 |
| 灵活性 | 低 | 高（总结、分类、生成、推理） |
| 风险 | 逻辑写死 | 可能幻觉，需要校验节点 |

AI 工作流不是「全自动魔法」，而是 **在可控流程里用 AI 处理不确定环节**。

---

## 典型组成

```text
触发器 → 上下文准备 → AI 处理 → 校验/规则 → 工具调用 → 输出/通知 →（可选）人工审核
```

| 环节 | 做什么 |
|---|---|
| **触发** | 新工单、定时任务、Webhook、用户提问 |
| **上下文** | 拉文档、查库、读历史、RAG 检索 |
| **AI 节点** | 分类、摘要、生成、代码建议 |
| **工具** | 调 API、写数据库、发邮件、创建 PR |
| **分支** | 按置信度/分类走不同路径 |
| **人工** | 低置信度、高风险时人工确认 |
| **观测** | 日志、成本、成功率、反馈回流 |

## 五种常见模式

### 1. 链式（Chain）

```text
用户问题 → 检索知识库 → LLM 回答 → 格式化输出
```

步骤固定，适合 FAQ、固定 RAG。

### 2. 路由（Router）

```text
工单 → AI 判类型（技术/商务/投诉）→ 分别走不同处理链
```

省成本：简单问题不走大模型全套。见 [[AI/00-AI学习体系/02-概念库/01-模型层/08-Model Routing|Model Routing]]。

### 3. 并行（Parallel）

```text
竞品资料 → 并行：价格 + 功能 + 风险 → 合并成报告
```

### 4. 人机协同（Human-in-the-loop）

```text
AI 生成回复 → 客服确认 → 发送给客户
```

### 5. Agent 式（多步自主）

```text
目标：查生产故障 → 查日志 → 查 DB → 给结论
```

模型自己决定下一步；需 **步数上限、权限白名单**。见 [[AI/00-AI学习体系/02-概念库/03-Agent系统/02-ReAct与Agent范式|ReAct与Agent范式]]。

## 开发向示例：代码评审辅助

```text
1. 触发：PR 创建
2. 拉取 diff + 相关模块文档（RAG）
3. LLM：安全/性能/规范检查
4. 规则引擎：必须通过项（测试、lint）
5. 输出：评审意见草稿
6. 人工：工程师最终 merge
```

## 搭建方式

| 方式 | 适合谁 | 代表 |
|---|---|---|
| **可视化编排** | 产品、运营、快速验证 | Dify、Coze、n8n + LLM |
| **代码编排** | 研发、深度定制 | LangGraph、LangChain、DSPy |
| **平台内置** | 已有业务系统 | 飞书/钉钉 AI、各云 Agent 平台 |
| **IDE 内嵌** | 个人效率 | Cursor Rules、Skills |

框架对比见 [[AI/00-AI学习体系/02-概念库/06-工程生态/03-应用层框架|应用层框架]]。

## 做好 AI 工作流的六条原则

1. **任务拆小**：一个节点只做一件事（分类、摘要、生成分开）
2. **上下文可控**：限定输入、必要时 RAG；见 [[AI/00-AI学习体系/02-概念库/06-工程生态/02-Context Engineering|Context Engineering]]
3. **输出结构化**：JSON / 固定模板，方便下游处理
4. **设兜底**：超时、解析失败、低置信度 → 转人工或重试
5. **可观测**：记录 prompt、token、耗时、反馈
6. **权限与安全**：工具调用、DB、生产操作要白名单

## 适合 / 不适合的场景

| 适合 | 不太适合 |
|---|---|
| 客服分类与初回复 | 强实时、零容错纯计算 |
| 文档摘要、周报 | 无审计要求的随意聊天 |
| 代码审查草稿 | 只靠 LLM 自评就上线的合规场景 |
| 非结构化信息抽取 | |
| 内部知识库问答（RAG） | |
| 运维告警**初步**分析（需权限） | |

## 与 Graph、Loop、Agent 的关系

```text
AI 工作流（业务层）
  └─ Graph（结构层）：节点 + 边 + State
       └─ Loop（控制层）：某几步是否反复执行
            └─ Agent：Loop 里由 LLM 决定走哪条边
```

| 概念 | 更贴近 |
|---|---|
| **Graph** | 工作流骨架 |
| **Loop** | 重试、反思、多轮改进 |
| **Agent** | 路径不确定时的自主决策 |

**不是二选一**：常见做法是 **Workflow 包 Agent**（外壳可控，中间一段开放推理）。

---

## 选型口诀

```text
步骤清楚、要审计、要上线     → Workflow
步骤多、要可视化调试          → Graph 编排（LangGraph / Dify）
某步要反复试直到达标          → 规则 Loop（仍 Workflow）
路径不确定、工具多            → Agent（外面再套 Workflow 约束）
```

90% toB：**Workflow + 可选规则 Loop** 即可；见 [[AI/00-AI学习体系/02-概念库/03-Agent系统/01-Workflow vs Agent|Workflow vs Agent]]。

## 自评与验收

工作流里常用「生成 → LLM 自检 → 不满意再改」的 Loop，但**不能单靠 LLM 说「满意了」就结束**。

原因与做法见 [[AI/00-AI学习体系/02-概念库/05-评测/03-LLM-as-a-Judge|LLM-as-a-Judge]] 中「工作流中的自评与硬校验」一节。
