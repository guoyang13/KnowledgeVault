# LLM-as-a-Judge

> 用强模型作为裁判评估回答质量，适合开放式问答、对话、摘要、RAG 和 Agent 任务。
>
> 更新时间：2026-07-10。

## 关键点

- **评测形式**：pointwise 打分、pairwise 对比、ranking 排序、rubric 分项评分。
- **适用场景**：没有唯一标准答案，但需要比较帮助性、准确性、完整性、引用质量。
- **主要风险**：长度偏好、位置偏好、自家模型偏好、风格偏好、提示词敏感。
- **校准方式**：混入人工标注集、随机交换 A/B 顺序、多裁判投票、固定 rubric。

## 工作流中的自评与硬校验

> 常见疑问：**为什么不直接交给 LLM 判断「是否得到满意结果」？**
>
> 很多 Agent / Loop 确实用 LLM 自评（生成 → 自检 → 不满意重写），但生产里**很少只靠 LLM 一句「我满意了」就结束**。

### 可以交给 LLM 评什么（软判断）

| 适合 | 例子 |
|---|---|
| 文风、结构、是否答到题 | 摘要是否够短、语气是否合适 |
| 多稿中选较好的一版 | Best-of-N 里用 judge 排序 |
| 分类置信度（配合阈值） | 意图不清时转人工 |
| 探索性草稿 | 错了可改，非对外发布 |

### 不能单靠 LLM 评什么（硬判断）

| 问题 | 说明 |
|---|---|
| **幻觉** | 自检时也会编「已核实」 |
| **过度自信** | 错答案也打高分 |
| **标准漂移** | 多轮后越来越松，提前喊「完成」 |
| **事实无法验证** | 库存、金额、接口是否存在——模型不知道 |
| **合规与追责** | 「LLM 说满意」无法审计 |

### 六种不能只靠 LLM 自评的原因

#### 1. LLM 不擅长可靠判断「对不对」

适合评「像不像对」；不适合单独评「事实对不对、业务合不合规、代码能否跑通」。

#### 2. 「满意」没有统一标准

用户要简短、产品要完整、法务要免责——**当前以谁为准**必须外置为规则或 rubric，不能靠模型感觉。

#### 3. 成本与延迟

```text
生成 → 自评 → 不满意 → 再生成 → 再自评 → …
```

每多一轮 = 多次 API 调用；必须硬设 `max_iterations` / token 预算——这本身又是**人为规则**。

#### 4. 责任与合规

金融、医疗、对外客服、生产变更需要：**谁批准、依据是什么、错了怎么追责**。工作流里的人工节点、规则引擎、自动化测试是为了**可审计**。

#### 5. 有些结果 LLM 根本验证不了

| 任务 | LLM 自评 | 更靠谱 |
|---|---|---|
| 代码对不对 | 「看起来对」 | **编译、单测、lint** |
| SQL 是否拖垮库 | 猜 | **EXPLAIN、限流、只读** |
| 金额、库存 | 猜 | **查库、对账规则** |
| 接口是否可用 | 猜 | **真实 HTTP 调用** |

正确模式：

```text
LLM 生成 → 确定性系统验证 → 验证通过才算满意
```

#### 6. 自己批改自己卷子

生成与评判同一模型时，容易合理化前面的错误。更好：**生成模型 + 独立校验**（规则 / 测试 / 专用 judge 模型 / 人）。

### 推荐组合（生产常见）

```text
LLM 软评（结构、相关性、草稿质量）
  + 规则/测试/工具 硬验（schema、单测、查库、API）
  + 低置信度 → 人工
  + max_retries / recursion_limit
```

与 [[AI/00-AI学习体系/02-概念库/02-训练与推理/03-PRM与ORM|PRM与ORM]] 的关系：

- **ORM（结果奖励）**：看最终对不对——对应硬校验、测试、查库。
- **PRM（过程奖励）**：看中间步骤——可用于 Agent 多步，但仍需外部 verifier。

与 [[AI/00-AI学习体系/02-概念库/03-Agent系统/11-AI工作流-Graph与Loop|AI工作流-Graph与Loop]] 中 **Evaluator–Optimizer Loop** 的关系：

- Loop 里可以用 LLM 当 Evaluator；
- **Optimizer 是否继续** 应由 **规则 + 上限 + 硬门禁** 共同决定，不能只有 LLM 说「够了」。

### 何时可以「 mostly 交给 LLM」

| 场景 | 建议 |
|---|---|
| 润色、内部草稿 | LLM 自评 + 人扫一眼 |
| 生产 toB、对外发送 | 必须硬校验 + 人工或规则放行 |
| Agent 多步排查 | LLM 决定**过程**下一步；**最终动作**（发邮件、改库）走硬门禁 |

### 一句话

> **可以让 LLM 参与判断「是否够好」，但不能只靠它。**
> 满意 = LLM 软评 + 规则/测试/工具硬验 + 必要时人工。
