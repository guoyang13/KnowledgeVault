# AI 工程选型原则 2026

> 更新时间：2026-07-01。
> 目标：从“追最新模型”转向“按任务设计系统”。

## 先问任务，不先问模型

选型前先判断任务类型：

| 任务 | 优先能力 |
|---|---|
| 简单分类/抽取 | 低成本、结构化输出、稳定性 |
| 复杂推理/代码 | reasoning、工具调用、长任务能力 |
| 私有知识问答 | RAG、引用、检索评测、权限 |
| 数据分析 | 代码执行、文件读取、可视化、审计 |
| 客服/销售 | 低延迟、语气稳定、合规、CRM 工具 |
| Coding Agent | repo 理解、文件编辑、测试、回滚 |
| 浏览器/桌面自动化 | computer use、权限隔离、人工审批 |
| 多媒体内容 | 图像/音频/视频模型与版权合规 |

## 模型不是系统

一个可上线 AI 应用至少包含：

```text
模型
+ prompt / system instruction
+ context construction
+ RAG / file search
+ tools / MCP servers
+ structured output
+ eval harness
+ logging / tracing
+ human approval
+ security policy
+ fallback / rollback
```

只换模型，通常无法解决系统性问题。

## 三层选型法

### 1. 能力层

看模型是否支持：

- 文本 / 图像 / 音频 / 视频。
- reasoning effort / thinking mode。
- 函数调用 / tool use。
- structured output。
- 长上下文。
- 文件搜索。
- 代码执行。
- computer use。

### 2. 工程层

看平台是否支持：

- API 稳定性。
- streaming。
- batch。
- prompt caching。
- tracing。
- fine-tuning / distillation。
- MCP / connectors。
- 权限隔离。
- 企业数据策略。

### 3. 业务层

看是否满足：

- 成本。
- 延迟。
- 数据合规。
- 可解释/可审计。
- 私有化部署。
- 中文效果。
- 供应商锁定风险。
- 故障兜底。

## 闭源 API 适合什么

适合：

- 需要最强通用能力。
- 复杂 reasoning / coding / agent。
- 希望快速上线，不想维护推理基础设施。
- 接受数据传给第三方 API。

注意：

- 成本和限流。
- 数据合规。
- 模型版本变化。
- 供应商锁定。

## 开放权重模型适合什么

适合：

- 私有化部署。
- 数据不能出域。
- 中文/行业定制。
- 大规模低成本批处理。
- 本地 RAG。
- 可控微调和蒸馏。

注意：

- 推理基础设施成本。
- 模型部署和量化。
- 评测和安全兜底要自己做。
- 版本升级和模型治理。

## 长上下文和 RAG 怎么取舍

长上下文适合：

- 少量长文档整体阅读。
- 需要跨文档综合。
- 上下文一次性强相关。

RAG 适合：

- 文档库大。
- 知识频繁更新。
- 需要权限过滤。
- 需要引用溯源。
- 需要控制成本。

最佳实践通常是混合：

```text
RAG 先召回
→ rerank 精排
→ 摘要压缩
→ 长上下文模型综合
→ 引用和校验
```

## Agent 上线前必须评估

Agent 不是“给工具就行”，上线前至少评估：

- 工具权限是否最小化。
- 是否有人工审批点。
- 是否能回放执行轨迹。
- 是否能限制花费和循环次数。
- 是否能防 prompt injection。
- 失败时是否能停止和降级。
- 是否有任务级 eval。

## 一套推荐落地路径

1. 选 20-50 个真实业务问题，做最小 eval set。
2. 用强闭源模型做 baseline。
3. 加 RAG/工具/结构化输出，观察提升来自哪里。
4. 用小模型或开放模型替换简单环节。
5. 建立日志、trace、失败样本库。
6. 做权限和安全设计。
7. 再考虑 fine-tuning 或私有化。

## 反直觉经验

- 最新模型不一定最适合生产。
- 上下文越长，不代表回答越准。
- Agent 能力越强，权限风险越高。
- RAG 的失败多数发生在检索，不在生成。
- 小模型配好路由，可能比单一大模型更省钱稳定。
- 没有 eval 的 AI 应用，优化基本靠感觉。

## 一句话

2026 年做 AI 工程，核心能力不是会调用某个模型，而是能把模型、上下文、工具、检索、评测和安全编排成可靠系统。
