# 2026 技术趋势速查

> 更新时间：2026-07-01。
> 用来快速理解“最近 AI 在变什么”。每个趋势都尽量链接到已有基础笔记。

## 1. Reasoning / Thinking 成为基础能力

以前：

- Prompt 里写“step by step”。
- CoT 主要是提示技巧。

现在：

- 模型训练阶段就强化推理过程。
- API 提供 `reasoning_effort`、thinking budget、think / non-think 等控制。
- 强模型在复杂任务中会主动花更多 token 做规划和验证。

## 2. Hybrid Reasoning 取代单一模式

同一个模型支持：

- 快答：低延迟、低成本。
- 深思：高准确率、高成本。

这会改变应用架构：

- 简单问题走快路径。
- 复杂问题升级 reasoning。
- 失败或低置信度时 fallback 到强模型。

## 3. 长上下文变强，但 RAG 没有消失

1M token 甚至更长上下文正在普及，但它解决的是“能放进去”，不等于“能稳定用好”。

仍然需要：

- 文档切分。
- 检索。
- rerank。
- 摘要压缩。
- 引用定位。
- 上下文去噪。

## 4. Agent 产品化

Agent 不再只是“LLM + tools”的 demo，而是逐渐变成完整工程系统：

- 任务规划。
- 工具调用。
- 浏览器/桌面操作。
- 文件读写。
- 后台任务。
- 人工审批。
- 运行日志。
- 评测与回放。

## 5. MCP 成为工具生态接口

MCP 的意义不是“又一个框架”，而是把工具/资源接入标准化。

关键变化：

- 工具不再只属于某个 Agent 框架。
- 文件、数据库、浏览器、SaaS、代码仓库可以作为标准 resources/tools 暴露。
- Agent 可以复用已有 MCP Server，而不是每个应用重新造连接器。

## 6. Coding Agent 成为最先成熟的 Agent 场景

原因：

- 代码仓库是结构化环境。
- 任务有明确产物。
- 可以运行测试验证。
- 失败可回滚。
- benchmark 较成熟，如 SWE-bench、Terminal-Bench。

## 8. 开放权重模型进入工程选型核心

开放权重模型不再只是“玩具模型”，而是可以用于：

- 私有化部署。
- 本地 RAG。
- 中文业务场景。
- 成本敏感任务。
- 数据不出域的企业应用。
- 小模型路由和蒸馏。

代表路线：

- Llama 4：开放权重、多模态、MoE、长上下文。
- Qwen3：中文/多语、thinking 模式、MoE、Agent/MCP。
- DeepSeek：低成本 reasoning、MoE、API 兼容。
- Mistral：企业部署、开放模型、reasoning、语音/OCR。

## 9. 评测从 benchmark 分数转向系统评测

单个模型分数越来越不够用，因为真实应用由多个组件组成：

```text
模型 + prompt + 检索 + 工具 + agent loop + memory + 权限 + 兜底
```

因此要评测：

- 任务完成率。
- 成本。
- 延迟。
- 工具调用正确率。
- 引用准确率。
- 安全拒答和越权行为。
- 人工接管率。

## 一句话总结

2026 年 AI 的主线不是“更会聊天”，而是：

> 模型开始具备可控推理、长上下文、多模态、工具调用和 Agent 执行能力，工程重点从 prompt 转向 context、tools、eval、security 和 workflow。
