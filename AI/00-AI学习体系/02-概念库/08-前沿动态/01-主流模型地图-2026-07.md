# 主流模型地图 2026-07

> 更新时间：2026-07-01。
> 这不是排行榜，而是学习和工程选型地图：看每家模型的主打方向、使用边界和应该关联哪些概念。

## 快速结论

| 方向 | 当前重点 |
|---|---|
| 前沿闭源模型 | OpenAI GPT-5.5 / GPT-5.6 preview、Claude Fable 5 / Opus 4.8 / Sonnet 5、Gemini 3 系 |
| 开放权重模型 | Llama 4 Scout/Maverick、Qwen3、DeepSeek V4 / V3.1、Mistral Magistral/Medium 系 |
| 推理模型 | Thinking / reasoning effort / hybrid mode 成为主流能力 |
| 长上下文 | 1M token 上下文已进入主流模型，但仍需要检索、压缩和上下文工程 |
| Agent 能力 | Tool use、Computer Use、Deep Research、Coding Agent、MCP 集成成为平台能力 |
| 多模态 | 文本 + 图像已是标配，音频、视频、屏幕操作和多模态 embedding 加速成熟 |

## OpenAI

当前学习重点：

- GPT-5.5 作为复杂推理和代码任务的旗舰入口。
- GPT-5.4 mini / nano 面向低延迟和低成本。
- GPT-5.6 处于 trusted partners preview，不能把它当作普遍可用能力。
- Responses API、工具调用、web/file search、computer use、Agents SDK 是工程主线。

应该关联：

- [[AI/00-AI学习体系/02-概念库/01-模型层/03-推理模型|推理模型]]
- [[AI/00-AI学习体系/02-概念库/01-模型层/08-Model Routing|Model Routing]]
- [[AI/00-AI学习体系/02-概念库/03-Agent系统/03-Tool Use与Function Calling|Tool Use与Function Calling]]
- [[AI/00-AI学习体系/02-概念库/03-Agent系统/07-Computer Use与Browser Agent|Computer Use与Browser Agent]]

工程判断：

- 复杂代码、长任务、Agent 任务优先强模型。
- 简单分类、抽取、格式转换、批处理优先 mini/nano。
- 有工具和文件检索需求时，不要只看裸模型能力，要看平台工具链。

来源：

- https://platform.openai.com/docs/models

## Anthropic Claude

当前学习重点：

- Claude Fable 5 是 Anthropic 最强的广泛发布模型。
- Claude Mythos 5 面向 Project Glasswing，属于受限/邀请制场景。
- Claude Opus 4.8、Sonnet 5、Haiku 4.5 构成能力、成本、速度梯度。
- Claude 4 之后的核心关键词是 agentic coding、extended/adaptive thinking、工具使用和 memory files。

应该关联：

- [[AI/00-AI学习体系/02-概念库/03-Agent系统/05-Agent Harness|Agent Harness]]
- [[AI/00-AI学习体系/02-概念库/03-Agent系统/08-Agent Memory|Agent Memory]]
- [[AI/00-AI学习体系/02-概念库/06-工程生态/01-Coding Agent|Coding Agent]]

工程判断：

- Claude 系非常适合长代码库理解、编辑、长任务协作。
- 选择模型时要区分 Opus、Sonnet、Haiku 的成本与延迟。
- “extended thinking + tools”适合复杂任务，但要有明确权限边界和可观测性。

来源：

- https://docs.anthropic.com/en/docs/about-claude/models/overview
- https://www.anthropic.com/news/claude-4

## Google Gemini

当前学习重点：

- Gemini 3 系成为 Google API 主线，Gemini 3.5 Flash 是稳定入口之一。
- Gemini 2.5 Pro/Flash 仍是重要基线，2.5 Pro 强调 deep reasoning 和 coding。
- Gemini API 已经把 Search、Maps、Code Execution、URL Context、Computer Use、File Search 等工具放进工程体系。
- Gemini Embedding 2 标志着多模态 embedding 正在成为 RAG 新方向。

应该关联：

- [[AI/00-AI学习体系/02-概念库/01-模型层/04-多模态模型|多模态模型]]
- [[AI/00-AI学习体系/02-概念库/04-RAG进阶/03-Embedding模型与向量检索|Embedding模型与向量检索]]
- [[AI/00-AI学习体系/02-概念库/03-Agent系统/07-Computer Use与Browser Agent|Computer Use与Browser Agent]]

工程判断：

- 如果需求重度依赖 Google 生态、搜索、地图、视频、语音和多模态，可以优先关注 Gemini。
- Preview/latest/experimental 模型要谨慎进生产，稳定模型优先。

来源：

- https://ai.google.dev/gemini-api/docs/models

## Meta Llama

当前学习重点：

- Llama 4 Scout 和 Maverick 是开放权重、多模态、MoE 路线的重要代表。
- Scout 强调超长上下文，公开资料显示上下文可达 10M token 级别。
- Maverick 强调性价比和多模态通用能力。
- Behemoth 是更大教师模型，主要用于蒸馏和能力迁移。

应该关联：

- [[AI/00-AI学习体系/02-概念库/01-模型层/02-MoE|MoE]]
- [[AI/00-AI学习体系/02-概念库/01-模型层/04-多模态模型|多模态模型]]
- [[AI/00-AI学习体系/02-概念库/01-模型层/07-上下文与KV Cache|上下文与KV Cache]]

工程判断：

- Llama 适合私有化、开放生态、本地微调、云厂商多平台部署。
- 超长上下文能力要结合真实检索准确率和推理成本评估，不能只看窗口大小。

来源：

- https://ai.meta.com/blog/llama-4-multimodal-intelligence/

## 选型不要只看模型名

真正影响应用效果的是组合：

```text
模型能力
+ 上下文策略
+ 工具调用
+ 检索系统
+ 评测集
+ 成本/延迟预算
+ 数据合规
+ 失败兜底
```

所以工程选型应该从任务出发，而不是从“谁最新”出发。
